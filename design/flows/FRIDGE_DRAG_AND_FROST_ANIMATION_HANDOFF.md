# UI-002 冰箱拖拽与逐格冷冻动效交接方案

> 日期：2026-08-04  
> 关联任务：`UI-002`、`FRIDGE-002`  
> 关联用户故事：`US-011`  
> 当前状态：方案已确认，代码待工程师实施  
> 实现入口：`code/apps/mobile/lib/features/fridge/fridge_page.dart`

## 1. 问题与目标

当前冰箱食材 chip 的跨区移动存在两类体验问题：

1. 冷冻效果虽然按宽度分段，但本质仍是一个整高色块不断变宽，因此看起来像从左向右扫过，而不是独立小格逐个出现。
2. 动画触发依赖 Widget 重建、长按拖拽结构和短时间去重，导致长按、拖动经过区域或重复回调时可能提前播放、错播或重复播放。

本次目标：

- 冷冻与解冻必须表现为**二维独立小格逐个出现或消失**。
- 动画只能发生在食材被最终目标区域正式接收、数据迁移成功并挂载到目标位置之后。
- 长按、拖动开始、拖过区域、取消拖动和同区排序均不得触发冷冻/解冻动画。
- 快速连续操作、同名多批次和页面重建时不得让错误食材播放旧动画。

## 2. 范围与非目标

### 2.1 本次范围

- 冰箱库存页食材 chip 的长按拖拽生命周期。
- 分区内排序和跨分区移动的提交边界。
- 进入冷冻区与离开冷冻区的逐格动画。
- 拖拽反馈、原位置占位和目标区高亮。
- 保存失败、减少动态、快速连续拖动和同名食材等边界。

### 2.2 非目标

- 不改变库存批次的数据字段、推荐算法或扣减逻辑。
- 不为冷藏、常温、其他区增加额外颜色过渡。
- 不增加弹跳、缩放、旋转、粒子、音效等装饰性动画。
- 不通过延长现有横向填充动画来伪装“逐格出现”。
- 本文不包含源代码；工程师根据规则实施。

## 3. 唯一交互状态机

一次拖拽必须按以下状态单向流转：

```text
idle
→ pressing
→ dragging
→ accepted
→ committing
→ mountedAtTarget
→ arrivalAnimation
→ idle
```

异常分支：

```text
pressing / dragging
→ cancelled
→ idle

accepted / committing
→ commitFailed
→ restoreOriginalPosition
→ idle
```

各状态允许的视觉行为：

| 状态 | 允许的视觉反馈 | 禁止行为 |
|---|---|---|
| `idle` | chip 正常静止 | 不自动重播历史动画 |
| `pressing` | 可显示静态按压态；建议取消水波纹 | 不播放冰冻、解冻、颜色扫动 |
| `dragging` | 静态拖拽影子；候选目标区高亮；原位固定占位 | 不改变库存位置，不播放到达动画 |
| `accepted` | 最终目标区确认接收 | 不在数据提交前播放成功动画 |
| `committing` | 保持拖拽结束后的稳定布局，可显示轻量保存中状态 | 不播放冰冻成功动画 |
| `mountedAtTarget` | 新位置 chip 已使用最终业务状态挂载 | 只允许消费本次唯一到达事件 |
| `arrivalAnimation` | 仅目标 chip 播放一次逐格冷冻或解冻 | 不影响其他 chip，不接受旧事件重播 |
| `cancelled` | 恢复原位置 | 不改变数据，不播放动画 |
| `commitFailed` | 恢复原位置并显示失败提示 | 不展示成功动画 |

## 4. 动画触发矩阵

| 用户操作 | 数据结果 | 动画结果 |
|---|---|---|
| 长按但不移动 | 不变 | 无动画 |
| 开始拖拽 | 不变 | 仅静态拖拽影子和目标区高亮 |
| 拖过冷冻区但未松手 | 不变 | 无冷冻动画 |
| 松手到无效区域 | 不变 | 无动画，恢复原位置 |
| 同一区域内排序 | 顺序更新 | 无冷冻/解冻动画 |
| 冷藏区 ↔ 常温区/其他区 | 区域更新 | 无颜色动画 |
| 常温区 ↔ 其他区 | 区域更新 | 无颜色动画 |
| 非冷冻区 → 冷冻区 | 保存成功后迁移 | 目标位置逐格冷冻一次 |
| 冷冻区 → 非冷冻区 | 保存成功后迁移 | 目标位置逐格解冻一次 |
| 拖过多个区域后放入最终区域 | 只提交最终区域 | 仅最终区域目标 chip 播放一次 |
| 保存失败 | 恢复原位置 | 无成功动画；显示失败提示 |
| 系统减少动态 | 正常提交 | 直接切换最终视觉，不播放逐格动画 |

**唯一触发条件**：最终目标的接收回调完成有效性判断，库存移动保存成功，目标位置 chip 已挂载，并收到本次未消费的到达事件。

以下事件绝不能直接触发冷冻/解冻：按下、长按识别成功、拖拽开始、进入候选区域、目标预判、指针移动、Widget 重建、筛选变化、分区展开/收起、无效释放。

## 5. 拖放提交边界

### 5.1 推荐结构：每个分区只有一个最终接收者

- 每个冰箱分区保留一个负责最终提交的拖放目标。
- 指针位于分区内部时，根据纵向或网格位置计算插入序号；chip 本身不再作为第二个会提交数据的目标。
- 候选目标只负责“能否接收”和高亮，不修改数据。
- 松手后只有最终命中的分区目标执行一次移动或排序提交。

这样可以直接消除“chip 级目标 + 分区级目标”先后回调所造成的双提交竞态。

### 5.2 如果短期不能移除嵌套目标

必须使用拖拽会话的一次性消费规则：

- 每次长按拖拽开始时生成唯一 `dragSessionId`。
- 会话中只能有一个目标把 `handled` 从 false 改为 true。
- 后续目标即使收到回调，也只能返回，不得再次提交。
- 禁止继续使用“同名食材 + 250ms 时间窗口”判断是否重复；时间窗口会在慢设备、快速连续拖动和同名食材场景中误判。

## 6. 动画事件身份

动画事件不得只使用食材显示名称或列表下标识别。每次到达事件至少包含：

| 字段 | 用途 |
|---|---|
| `dragSessionId` | 标识一次完整拖拽 |
| `moveEventId` | 标识一次唯一提交，必须单调递增或全局唯一 |
| `stableItemId` | 标识实际移动的聚合项或批次集合 |
| `sourceZone` | 原区域 |
| `targetZone` | 最终区域 |
| `animationKind` | `freezeIn`、`thawOut` 或 `none` |

稳定身份要求：

- 优先使用聚合实体自己的稳定 ID。
- 如果当前没有聚合 ID，使用规范食材 ID与排序后的批次 ID 集合形成稳定身份；不得使用显示名称或当前列表下标。
- 同名不同批次或同名不同聚合项不能互相消费动画事件。
- 目标 chip 记录最后消费的 `moveEventId`；同一事件只能播放一次。
- 页面重建、筛选、展开/收起、返回页面和主题变化都不能重新消费旧事件。
- 动画结束后可以清理事件，但不能用“下一帧统一清理”作为避免重复播放的唯一保障。

## 7. 拖拽组件职责拆分

现有正式 chip、拖拽影子和原位占位不应共用一个会自行启动动画的有状态组件。建议拆分职责：

1. **静态食材视觉**：只负责名称、数量、状态、图标、边框和背景的最终样式，不持有动画控制器。
2. **正式目标 chip**：包裹静态视觉，只在目标列表中消费唯一到达事件并播放逐格动画。
3. **拖拽影子**：静态快照，不持有动画控制器，不接收 pending 事件，不带水波纹。
4. **原位置占位**：固定原 chip 的尺寸和布局，不重新创建另一份可动画 chip。

长按阶段建议关闭或弱化 InkWell 的 splash/highlight，避免按压反馈被误认为动画提前触发。

## 8. 二维逐格冷冻视觉规范

### 8.1 网格形态

- 将 chip 的可见背景区域切成真正的二维小格，格子约 `12–14dp`。
- 根据 chip 实际高度形成至少 2 行，常规 chip 目标为 2–3 行；列数随宽度动态计算。
- 格子之间保留约 `1dp` 的视觉缝隙或使用背景底色形成分隔。
- 网格整体裁切在 chip 原有像素缺角轮廓内，不能溢出圆角或缺角边界。
- 每个格子是独立状态，不能再绘制“从 0 增长到 progress×width 的整高矩形”。

### 8.2 出现顺序

采用确定性的“冰核向外扩散”顺序：

1. 从靠近 chip 图标一侧、垂直居中的一个格子作为冰核。
2. 按与冰核的曼哈顿距离由近到远排序。
3. 同一距离内按固定顺时针顺序排列，保证结果稳定。
4. 每个动画 tick 只新增一个完整格子；不得一次出现整列、整行或竖条。
5. 解冻使用完全相反的顺序逐格消失。

这种顺序仍能让用户看清“一格一格”，同时避免重新形成横向扫描线。

### 8.3 时间与插值

- 推荐总时长：`450–650ms`。
- 每格间隔建议 `24–36ms`，根据格子总数计算并将总时长限制在上述范围。
- 格子的状态为离散开/关，不做透明度渐变，不做宽度插值。
- 不添加额外弹跳、缩放或抖动。
- 动画完成后必须稳定停在最终状态：冷冻区全部格子为冰冻样式，其他区全部格子为正常样式。

### 8.4 描边、投影和图标

- 描边、投影和图标颜色不得继续使用连续 `Color.lerp` 跟随进度，否则仍会产生平滑扫色感。
- 冷冻时可在第一个格子出现时一次性切换为冷冻描边/图标；解冻时在最后一个格子消失后一次性恢复正常样式。
- 动画主体只能是二维小格，其他样式只做离散状态切换。

## 9. 数据提交与失败处理

推荐顺序：

1. 最终目标区接收拖放。
2. 计算源区、目标区和插入位置。
3. 若是无效移动或同区未改变顺序，直接结束，不创建动画事件。
4. 提交库存位置/顺序持久化。
5. 保存成功后更新页面数据并将 chip 挂载到最终位置。
6. 生成唯一到达事件。
7. 目标 chip 消费事件并播放一次动画。

保存失败时：

- 数据和视觉都恢复到原位置。
- 不生成成功动画事件。
- 显示明确中文提示，例如“移动失败，食材已放回原位置，请重试”。
- 不依赖重新进入页面恢复一致性。

## 10. 目标区反馈

拖动过程中可以提供反馈，但必须与到达动画明确区分：

- 可接收区域：仅改变分区边框、背景或插入指示线。
- 不可接收区域：不高亮，或显示禁止指针样式。
- 当前源区域：同区排序时仅显示插入位置。
- 目标区高亮必须在拖拽结束或取消后立即清除。
- 任何目标区高亮都不能改变食材 chip 的冷冻状态。

## 11. 系统状态覆盖

| 状态 | 处理规则 |
|---|---|
| 默认态 | chip 使用所在分区的最终静态视觉 |
| 空分区 | 可以作为有效目标；落入后先创建正式 chip，再按规则播放 |
| 加载态 | 禁止开始新的拖拽，避免对不完整列表提交 |
| 成功态 | 仅成功提交的目标 chip 播放一次 |
| 错误态 | 恢复原位置并提示，不播放成功动画 |
| 弱网/离线态 | 库存为本地能力，行为与在线一致；不得因离线阻断拖拽 |
| 权限拒绝态 | 本交互不需要系统权限，不得额外请求权限 |
| 极限内容态 | 超长名称、多批次、100+ 项、连续快速拖动时身份与布局稳定 |
| 游客态 | 与登录态具备相同本地拖拽能力 |
| 登录态 | 本地提交完成后再由同步层处理；远端同步不得重播本地到达动画 |

## 12. 减少动态与可访问性

当系统启用减少动态或 `MediaQuery.disableAnimations` 时：

- 数据提交和位置变化保持正常。
- 目标 chip 直接显示最终冷冻或非冷冻样式。
- 不播放逐格动画，也不以其他闪烁或淡入替代。
- 拖拽目标高亮仍可保留，但应为静态样式。

## 13. 针对现有实现的改造清单

工程师应围绕 `fridge_page.dart` 完成以下结构调整，不要仅调整动画时长或格子尺寸：

1. 将 `_applyDrop` 的动画标记生成时点移到持久化成功、目标 chip 挂载之后。
2. 用唯一事件对象替代当前仅按“食材名称 + 方向”识别的 `_pendingFrostAnim`。
3. 移除“250ms 时间窗口去重”；优先改为单一分区接收者，最低限度也要使用 `dragSessionId + handled`。
4. 将 `_buildDraggableChip` 中正式 child、feedback、childWhenDragging 的视觉与动画职责拆开。
5. 确保拖拽影子和原位占位没有动画控制器、pending 动画参数和水波纹。
6. 将 `_FrostFillPainter` 从增长矩形改为二维独立格子集合；每 tick 只改变一个格子的开/关状态。
7. 移除描边、投影和图标的连续颜色插值，改为离散状态切换。
8. 加入减少动态分支。
9. 对快速连续拖动、同名多批次、筛选重建和保存失败补充测试。

## 14. 完成定义

只有同时满足以下条件，才能认为本方案实现完成：

- 长按、拖动经过和无效释放均不触发冷冻/解冻动画。
- 只有最终落点提交成功后，目标位置食材播放一次动画。
- 冷冻效果能明显看到二维独立小格逐个出现，而不是整块、整列或横向扫描。
- 解冻为上述格子的逆序逐个消失。
- 同区排序和非冷冻区之间移动没有颜色动画。
- 快速连续移动和同名多批次不串动画。
- 保存失败不播放成功动画并恢复原位置。
- 页面重建、筛选、展开/收起不会重播旧动画。
- 减少动态设置下直接切换最终状态。
