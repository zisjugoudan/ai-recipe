# UI-006 AI 草稿确认页

- 所属模块：DESIGN-001 链接导入全流程
- 关联：US-005（AI 结果待确认）
- 目标：AI 结果必须经用户确认才能保存，必须可编辑、可查看来源证据。

## 功能清单

1. **顶部信息**：菜名、来源平台、原链接、解析状态。
2. **低置信度提醒条**：如「有 3 处内容需要确认」，带图标 + 文字（不止颜色）。
3. **菜谱预览**：封面、分类、标签、份量、耗时、难度。
4. **食材区**：食材名、用量、备注。
5. **步骤区**：步骤序号、操作、时间、火候、关联食材。
6. **原始证据入口**：查看来源文本、图片 OCR 片段、视频口播片段。
7. **低置信度字段表现**：
   - 低置信字段带图标 / 文字标签（不只用颜色）。
   - 点击字段 → 查看「AI 为什么这么填」：原文片段 / OCR 文本 / ASR 文本。
   - 用户修改后，低置信标记消失或转为「已确认」。
8. **底部操作**：
   - 保存菜谱（确认后存为正式菜谱 → 进详情页）。
   - 继续编辑（进编辑页 UI-008）。
   - 重新生成（按钮内像素 loader 跳跃后 toast，结果回草稿）。
   - 放弃草稿（二次确认后丢弃）。

## 重要规则

- 不允许 AI 结果直接覆盖已有菜谱。
- 保存前必须可编辑。
- 放弃草稿需确认。
- 重新生成结果进入草稿确认页，不自动保存，不与本地推荐混排。

## 页面结构

- 顶部：菜名 + 来源 + 解析状态 + 返回。
- 内容区：低置信提醒条 → 预览卡（菜名/分类/标签/份量/耗时/难度）→ 食材（含低置信字段可点）→ 步骤 → 原始证据折叠。
- 底部固定栏：保存 / 继续编辑 / 重新生成 / 放弃。

## 状态覆盖

| 状态 | 处理 |
|---|---|
| 待确认 | 3 处低置信，可点查看证据 |
| 用户修改后 | 低置信标记转「已确认」 |
| 重新生成 | 按钮 loader + toast，回草稿 |
| 放弃 | 二次确认 |

## 走查要点

- 低置信字段必须有「可点开看证据」的交互，且图标 / 文字明确。
- 重新生成、保存等耗时操作要接像素 loader 动效。
- 底部操作四按钮在窄屏需可滚动或分主次，不可挤出。
