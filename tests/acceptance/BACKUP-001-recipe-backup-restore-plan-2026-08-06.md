## 3. 方案走查步骤与预期结果

### 3.1 全量边界

**操作**

- 检查“全量”是否覆盖正式、草稿、归档、回收站菜谱，以及分类、关系、食材、步骤、标签、收藏、时间/版本/软删除字段和全部菜谱图片。
- 检查空库是否被定义为合法备份。
- 检查排除项是否明确。

**预期**

- 用户不能误把“只选几道菜”当成全量备份。
- 首版明确不包含库存、购物清单、制作记录、最近浏览、运行中任务/计时器、设置、凭证、模型、缓存和临时文件。
- 必需媒体缺失时必须失败，不生成看似成功但不完整的全量包。

### 3.2 文件格式与扩展性

**操作**

- 检查 `.airecipe-backup` 是否只是用户扩展名，内部为标准 ZIP。
- 检查 Manifest、Dataset、媒体索引和媒体对象是否分层。
- 检查归档格式版本、Dataset Schema 版本和 SQLite schemaVersion 是否独立。
- 检查未知 optional feature 与 required feature 的兼容策略。

**预期**

- 方案没有直接复制 SQLite，也没有使用巨型 JSON + Base64 图片。
- 后续增加库存、购物清单、制作记录、新媒体或新 Schema 时，可新增 Dataset Adapter 和 Migrator，不破坏旧版菜谱备份。
- 新应用能迁移旧备份；旧应用遇到未知必需能力时拒绝，遇到可选能力时允许明确跳过。

### 3.3 导出流水线

**操作**

- 检查导出是否包含一致性快照、统计、空间预检、临时目录、流式写入、哈希、归档复核、原子发布和失败清理。
- 检查媒体丢失和取消行为。

**预期**

- 文件只在完整校验通过后交付给用户。
- 失败或取消会清理临时文件，不留下半包。
- 全量包中的记录数、字节数和 SHA-256 可被导入端复核。

### 3.4 合并导入

**操作**

- 检查文件是否先进入 staging 和只读预检，再生成 ImportPlan。
- 检查新增、完全相同、可能重复、同 UUID 冲突和不可导入项是否可区分。
- 检查默认行为是否为合并。

**预期**

- 同 UUID 且内容一致可以安全跳过。
- 同 UUID 内容不同时必须由用户选择保留当前、使用备份或保留两份，不得静默覆盖。
- 仅名称相似不能自动认定为同一菜谱。
- 数据库与媒体提交失败时，当前库保持原状或完成回滚。

### 3.5 替换与回滚

**操作**

- 检查“替换当前库”是否位于高级恢复而不是默认入口。
- 检查执行前是否强制创建并验证当前库回滚备份。
- 检查恢复失败后的结论和清理方式。

**预期**

- 未能创建或验证回滚备份时，替换操作不能开始。
- 失败后必须明确显示“当前库未改变”或“已从回滚备份恢复”。
- 不允许数据库已替换但图片缺失，或媒体已写入但无数据库引用。

### 3.6 安全和交互状态

**操作**

- 检查 Zip Slip、Zip Bomb、重复路径、非法路径、大小/数量上限、Manifest/哈希校验和未知版本策略。
- 检查默认、空、统计、打包、成功、失败、选择文件、读取、预检、冲突、导入、损坏包、未来版本、权限拒绝、空间不足、离线、游客、登录和超大库状态。
- 检查隐私提示和凭证排除规则。

**预期**

- API Key、Token、Cookie 和安全存储引用不进入备份。
- 离线时功能仍可工作；游客与登录用户都能使用本地备份恢复。
- 用户取消文件选择不是错误。
- 备份包含备注和图片时明确提示不要公开分享。

### 3.7 事实源一致性

**操作**

- 对照产品需求、US-014、BACKUP-001、ADR-0034、R-020、架构方案和流程文档。

**预期**

- 全量边界、排除范围、默认合并、冲突不静默覆盖、替换前回滚、安全预检和扩展机制没有互相矛盾。
- Markdown/PDF/图片“内容导出”、本地全量备份和云同步被定义为三种独立能力。

## 6. 当前限制与实施前置

- 功能尚未实现，当前不能创建或恢复真实 `.airecipe-backup` 文件。
- 当前图片以设备路径字符串保存；稳定 `mediaAssetId`、SHA-256、MIME、大小、相对存储键、引用关系和清理账本尚未实现。
- 正式菜谱仍缺少完整来源 URL、canonical URL 和不可变来源证据快照契约。
- 加密只在归档能力中预留，首版方案不承诺加密备份。
- iOS 与 Android 的文档选择器、存储空间、后台中断和跨平台恢复尚未实机验证。
