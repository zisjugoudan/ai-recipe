> 状态：Android 核心验收通过（DONE）  
> 执行平台：Android 模拟器  
> iOS：本任务不验证

## 1. 问题与修复范围

修复前，首页顶部“有 N 个未完成的导入”虽然显示的是本地持久化任务数量，但点击事件复用了“添加菜谱”，因此会进入新建导入页，并可能再次创建同一链接的新任务。

本次实现将该提示改为独立的“打开已有任务”回调：

- 点击后把 `HomeSnapshot.unfinishedImportTasks.first` 对应的原任务交给应用壳。
- 应用壳使用原任务 `taskId` 打开导入进度页。
- 不调用新建导入流程，不通过链接重新创建任务。
- 多个未完成任务时，当前 P0 先打开创建时间最新的一项；完整导入记录列表不属于本缺陷范围。

## 2. 前置条件

1. 在 Android 模拟器安装并启动包含本次修改的最新应用。
2. App 内至少存在 1 个未完成导入任务，状态可以是：排队中、运行中断、待确认或失败。
3. 记下首页提示中的数量 `N`。
4. 记下准备恢复的原任务链接；如果有多个未完成任务，尽量同时记下最近创建任务的链接。
5. 本测试不要求重新配置或暴露 API Key；不要把 Key、Authorization、完整 Prompt 或完整模型响应放入截图和反馈。

## 3. 核心路径：点击后恢复原任务

1. 回到首页。
2. 确认顶部显示“有 N 个未完成的导入”。
3. 点击整条未完成导入提示。
4. 观察打开的页面和其中显示的来源链接。

### 预期结果

- 直接进入原任务的“解析中 / 解析失败 / 待确认”流程，而不是“添加菜谱”链接输入页。
- 页面显示的链接与原任务链接一致。
- 不需要再次粘贴或提交链接。
- 不出现第二条相同来源的新任务。

## 4. 数量与重复任务检查

1. 在原任务页面不执行“重新解析”、不重新提交链接，直接返回首页。
2. 再次查看顶部未完成数量。
3. 如果任务状态在此期间没有变为完成或取消，比较返回后的数量与点击前数量。
4. 再次点击提示，确认仍然进入同一个原任务。

### 预期结果

- 状态未变化时，数量仍为 `N`，不能因点击“继续处理”变为 `N + 1`。
- 第二次点击仍打开原任务，不出现同链接的重复任务。
- 如果原任务在后台恰好完成或被取消，数量可以按真实状态减少，但不能增加。

## 5. 多任务顺序（仅在已有 N > 1 时执行）

1. 确认首页提示数量大于 1。
2. 记下最近创建的未完成任务链接。
3. 点击提示。
4. 返回首页后，完成或取消当前任务，再次点击剩余提示。

### 预期结果

- 第一次打开最近创建的未完成任务。
- 当前任务完成或取消后，首页数量减少 1。
- 再次点击可以进入剩余任务，而不是进入新建页。

## 6. 各状态恢复检查（按现有样本选择执行）

### 排队中

- 点击后进入原任务并继续执行，不新建任务。

### 运行中断

- 强制停止 App 后重新启动，点击首页提示。
- 应恢复原任务并继续，不生成新的任务 ID 对应记录。

### 待确认

- 点击后进入原任务已有草稿的确认流程。
- 不重新调用 LLM 生成第二份草稿。

### 失败

- 点击后显示原任务的真实失败信息、重试或人工降级入口。
- 不自动新建任务，也不自动把用户带回链接输入页。

## 7. 完成/取消后的数量刷新

1. 从首页提示进入原任务。
2. 完成保存或取消该任务。
3. 返回首页，必要时下拉刷新一次。

### 预期结果

- 已完成或已取消的任务不再计入未完成数量。
- 有其他未完成任务时数量减少 1；没有其他任务时顶部提示消失。
- 不出现多余草稿或正式菜谱。

## 8. 强停重启检查

1. 保留至少一个未完成任务。
2. 强制停止 App。
3. 重新启动 App，进入首页。
4. 点击未完成提示。

### 预期结果

- 首页仍能读取持久化数量。
- 点击后恢复重启前的原任务。
- 不进入新建页，不产生重复任务。

## 11. 最终结论

- 首页提示已正确恢复原持久化任务，不再进入“添加菜谱”页。
- 数量在只打开并返回时保持 `12`，没有创建同链接重复任务。
- 多任务时优先打开最近创建任务，强停重启后仍可恢复原任务。
- 取消任务后未完成数量会减少，且没有多余草稿或正式菜谱。
- “成功完成并保存后数量减少”未执行，原因是 `BUG-003` 的真实小红书链接仍无法完成解析；该未执行项转由 `BUG-003` 后续端到端验证覆盖，不继续阻塞本入口缺陷。
- Android 核心验收通过，`BUG-004` 状态更新为 `DONE`。
- iOS 未验证。
