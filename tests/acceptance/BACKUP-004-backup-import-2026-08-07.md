## 1. 本轮交付边界

本轮实现的是「导入」半边（BACKUP-004 + BACKUP-005 的执行部分）：

- 预检流水线：staging（ZIP 安全检查 + 版本兼容 + SHA-256 校验）→ 预检当前库（只读）→ 生成 `BackupImportPlan`，全程不改变当前库。
- 默认合并模式：同 UUID 同内容跳过、同 UUID 不同内容进冲突、不同 UUID 但内容相同标为可能重复、仅名称相似不自动合并；冲突支持「保留当前 / 用备份覆盖 / 两者保留」。
- 替换模式（BACKUP-005）：替换前强制创建并验证回滚备份、二次确认、清空菜谱库范围后写入、清理孤儿图片；失败时回滚本次媒体并尽力从回滚备份恢复。
- 两阶段 + 清理账本：成功或失败均清理 staging 会话目录；应用启动时清理遗留 staging。

已交付代码位置（`code/apps/mobile/`）：

- 领域契约：`lib/domain/backup/backup_import_plan.dart`、`backup_import_repository.dart`、`backup_record_hashing.dart`（规范化内容哈希，排除图片设备路径/updatedAt/localVersion）

## 2. 前置材料

1. 阅读 `docs/architecture/RECIPE_BACKUP_RESTORE.md` 第 9/10/12/13 章。
2. 构建并安装当前 Android Debug APK（`flutter build apk --debug` + `adb install -r`）。
3. 准备至少两类备份文件：
   - **来源 A（当前库自身的备份）**：先创建一次全量备份，得到「A 备份」；再修改/新增/删除若干菜谱，使当前库与 A 备份不同。用于验证合并与替换。
   - **来源 B（故意损坏的备份）**：复制 A 备份改名 `.zip`，解压后删除 `media/sha256/` 下某张图片再重新压回 `.airecipe-backup`；或直接修改 `manifest.json` 的 `formatVersion` 为未来值。用于验证安全/损坏路径。

### 2.1 构建环境说明（2026-08-07 起生效，重要）

本机 `code/apps/mobile` 位于含中文的路径（`E:\AI\ai食谱\...`），有两处构建约束：

- **必须在 `C:\AIM`（目录联接 junction → `E:\AI\ai食谱\code\apps\mobile`）下运行所有 flutter 命令**，例如 `cd C:\AIM; flutter run` / `flutter build apk --debug`。原因：Flutter 的 shader 编译器 `impellerc` 无法写入含中文的路径，直接在真实路径构建会报 `ShaderCompilerException: Could not write file to ... shaders/ink_sparkle.frag`。`C:\AIM` 已创建为持久 junction，构建产物实际仍落在 `code/apps/mobile/build/`。
- **首次构建（或 `flutter clean` 后）需可访问 GitHub**：`sqlite3 3.5.0` 的 native assets hook 会从 `github.com/simolus3/sqlite3.dart/releases` 下载预编译库，本机无法直连 GitHub，需先设置代理环境变量再构建：
  ```powershell
  $env:HTTP_PROXY='http://127.0.0.1:7897'; $env:HTTPS_PROXY='http://127.0.0.1:7897'; flutter build apk --debug
  ```
  下载产物缓存在 `build/` 下，之后非 clean 构建无需再次联网（也不要求代理）。

## 4. 手动验收步骤与预期结果

前置：应用已安装并至少有 2 道以上带封面/轮播图的正式菜谱、1 个分类；已按第 2 节准备「A 备份」「B 备份」。

### 4.1 入口与选择文件（默认态 + 取消态）

**操作**

1. 进入「我的 → 数据与存储」，点击「从备份导入」。
2. 在「选择备份文件」页点击「选择备份文件」；先取消文件选择器，再正常选择 A 备份。

**预期**

- 页面标题「从备份导入」，副标题「数据与存储」。
- 取消文件选择器时停留在选择页，无错误提示，不创建任何会话。
- 系统文件选择器显示所有文件（`FileType.any`：自定义扩展名 `airecipe-backup` 无法在 Android 上映射 MIME，依赖系统过滤会直接报 "Unsupported filter"，因此改为选择后自行校验）。
- 选择非 `.airecipe-backup` 扩展名的文件时，页面提示「请选择 .airecipe-backup 备份文件。」并留在选择页。
- 选择正常文件后进入「正在分析备份…」加载态。

### 4.2 预检：安全校验与版本（错误态）

**操作**

1. 选择「B 备份」（损坏：删除媒体后重新打包）。
2. 选择「未来版本」备份（把 manifest 的 `formatVersion` 改大）。

**预期**

- 损坏备份：预检失败，返回选择页并显示中文错误（如「备份缺少 N 张图片，无法完整恢复」或媒体哈希不一致），不进入计划页，执行按钮不可用。
- 未来版本：显示「备份来自更新版本的应用」类可读错误，拒绝导入，不进入执行。
- Zip Slip / Zip Bomb / 重复路径 / 非法路径 / 单文件与总解压大小超限 / JSON 单行超长等恶意构造（若项目负责人有能力构造）：全部稳定失败并给出可读中文错误（`archive_security_limit` 等），不崩溃、不写盘。
- 预检失败后应用文档目录 `backups-import/`（staging 根目录）不残留本次会话目录。

### 4.3 计划展示（审阅态）

**操作**

1. 选择「A 备份」进入审阅页，核对统计卡。

**预期**

- 统计卡显示「新增菜谱」「跳过/重复」「冲突」数量；下方显示「N 分类 / M 图片」与待导入媒体体积。
- 「跳过」数量 = 备份中与当前库同 UUID 且内容完全一致的菜谱数（修改过或新增过的菜谱不计入）。
- 「冲突」数量 = 备份中与当前库同 UUID 但内容不同的菜谱 + 分类冲突数；「跳过/重复」中的重复 = 不同 UUID 但规范化内容哈希完全相同的可能重复项。
- 仅名称相似、内容不同的备份菜谱**不会**被自动合并，不会出现在跳过列表，只可能作为普通新增或冲突。
- 默认导入方式为「合并导入」；「合并/替换」切换可用。

### 4.4 合并导入（成功态 + 冲突策略）

**操作**

1. 保持「合并导入」，先逐个确认冲突列表出现（至少 1 条「同 ID 不同内容」冲突，若有分类冲突也显示）。
2. 对某条冲突选择「保留当前」：导入后该菜谱保持当前版本。
3. 对另一条冲突选择「用备份覆盖」：导入后该菜谱变为备份版本。
4. 对第三条冲突选择「两者保留」：导入后出现两份，备份副本为新的 UUID，且若其分类被双保留，菜谱的分类引用同步指向新分类。
5. 点击「开始导入」，观察执行页阶段文案与进度。

**预期**

- 冲突列表每条显示备份标题与当前标题；三态切换（保留当前 / 用备份覆盖 / 两者保留）即时反映到执行按钮。
- 执行阶段文案依次为：正在准备图片 → 正在写入菜谱库 → 正在完成导入；进度单调递增不倒退。
- 完成后「导入完成」页显示：写入 N 道菜谱、N 个分类，跳过 N 道菜谱、N 个分类，导入 N 个图片文件，数字与 4.3 计划一致。
- 按策略核对结果：保留当前 → 库中仍是当前版本；用备份覆盖 → 库中为备份版本；两者保留 → 两份都在（一份原 UUID 一份新 UUID），分类双保留时菜谱归属正确。
- 合并后原有菜谱、分类、回收站数据一个都不少；未涉及冲突的备份新增项进入库中。
- 合并完成后返回备份页；再次从备份导入同一 A 备份时，相同记录全部进入「跳过」，不产生重复。

### 4.5 替换恢复（BACKUP-005 执行部分）

**操作**

1. 重新选择 A 备份进入审阅页，切换「替换恢复」。
2. 核对「替换范围」提示，点击「开始替换」，在二次确认弹窗核对后确认。

**预期**

- 替换范围提示显示将被删除的当前菜谱数、分类数、图片文件数（来自预检，与实际库一致）。
- 二次确认弹窗标题「替换当前菜谱库？」并说明执行前自动创建回滚备份；取消则不做任何修改。
- 确认后执行阶段依次出现：正在创建回滚备份 → 正在准备图片 → 正在写入菜谱库 → 正在完成导入；回滚备份阶段耗时与一次全量导出相当。
- 完成后「导入完成」页显示「菜谱库已替换」摘要，并显示「回滚备份已保留」及文件路径（`ai-recipe-rollback-<时间戳>.airecipe-backup`，位于 `backups/`）。
- 替换后库内容与 A 备份完全一致（含回收站菜谱）；原库中独有的菜谱、分类与图片不再存在（图片文件被孤儿清理删除）。
- 替换不影响账号、API 密钥、设置与冰箱库存。

**替换失败恢复（可在开发库上制造，非必须）**

- 若在写入阶段制造失败（例如替换执行中杀进程后重新进入），重启后应用能重新打开且不残留损坏状态；staging 目录被启动清理；若写入失败，尽力从回滚备份恢复，页面显示「当前库未改变」或「已从回滚备份恢复」类结果，回滚备份文件保留。

### 4.6 取消与清理账本

**操作**

1. 执行导入（合并或替换）过程中点击「取消」。

**预期**

- 取消后回到审阅页并提示「导入已取消。」；本次未完成写入被回滚或清理，不残留半成品菜谱与孤儿图片。
- 执行中返回键被禁用（`PopScope`），防止误退导致状态不一致。
- 预检后未执行直接返回（或切换文件），`backups-import/` 会话目录被清理（`discardImportPreview` 或下次启动 `cleanupAbandonedImportSessions`）。
- 成功导入后会话目录也被清理，无残留。

### 4.7 本轮回归：删除性能 + 导入完成返回主界面刷新（2026-08-07）

**背景**：项目负责人反馈①回收站清空/批量删除太慢；②删除测试数据很慢；③导入完成后主界面仍显示旧数据，用户可能以为导入失败。已实施：批量永久删除 `permanentlyDeleteRecipesByIds`（单事务 500/批 IN 删除 + 级联清子表）、批量软删除 `softDeleteRecipesByIds`（单事务分批 UPDATE `deleted_at`）、`BackupPage` 导入返回后触发 `onDataChanged` 刷新（ProfilePage 透传）。

**操作**

1. 回收站清空/批量删除：先在回收站积累大量菜谱（至少 1000 条，可用「我的 → 开发者工具 → 生成性能测试菜谱」生成后软删除，或导入含回收站菜谱的大备份），进入「回收站 → 清空回收站」或多选后「永久删除」。
2. 删除测试数据：「我的 → 开发者工具 → 清空性能测试菜谱」。
3. 导入返回刷新：用大备份（或小备份）执行一次导入，完成后点「完成」返回主界面。

**预期**

1. 回收站清空/批量删除大数量（如 2000 条）在数秒内完成并回到空状态，不再长时间卡顿；删除期间有加载态反馈。
2. 「清空性能测试菜谱」瞬间完成并提示「已清空 N 条测试菜谱。」；「我的」页返回后计数归零。
3. 导入完成点「完成」返回主界面后：首页/菜谱库/回收站立即显示导入后的新数据（数据量大时显示既有加载态，不会停在导入前旧数据）；备份页「上次备份已创建/预估」统计同步刷新。
