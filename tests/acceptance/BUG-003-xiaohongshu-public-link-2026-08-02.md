# BUG-003：小红书公开分享链接导入异常验收记录

> 日期：2026-08-02  
> 最后更新：2026-08-02  
> 状态：`VERIFY`  
> 平台：Android（iOS 未验证）  
> 范围：Flutter 应用内公开内容获取、页面元数据解析、LLM 响应兼容、严格 Recipe Schema、导入任务与错误展示

## 1. 问题说明

项目负责人使用同一条公开的小红书 PC webshare 图文链接完成最新 Android 复测。LLM 设置页连接测试正常，任务已离开 `queued/0%`，先后进入“正在获取公开内容”和“正在生成结构化菜谱”，最终在生成阶段 `65%` 失败，稳定提示为“AI 返回的菜谱结构无效”，并显示“尝试 1/3 · 不可重试”。

该证据确认公开页面获取、小红书内容解析和 LLM 请求已经真实执行；当前根因收窄到纯语言模型返回文本的外层包装、截断/空内容，或字段类型不符合严格 Recipe Schema。不得继续把本轮失败归因于小红书页面无法获取。

项目负责人同时确认：失败后返回首页，该任务仍计入“未完成的导入”；再次打开失败页后没有可用的结束操作，现有恢复入口对不可重试失败无效。该交互问题独立登记为 `BUG-005`，必须通过用户主动执行 `failed → cancelled` 结束任务，不能通过查询时过滤 failed 隐藏。

为避免保存访问凭证或受限参数，本记录不保存完整分享 URL、`xsec_token`、Cookie、Authorization、API Key、完整页面正文、完整 Prompt 或完整模型响应。规范化样本为：

```text
https://www.xiaohongshu.com/explore/6a421c6b00000000170297f9
```

## 2. 验收目标

1. 合法的小红书 `https://www.xiaohongshu.com/explore/<note-id>` 分享链接能够被识别为小红书公开来源。
2. 导入启动前的能力校验、会话读取、Runner 创建失败必须转换为稳定、脱敏、可操作的错误，不得只显示页面通用异常。
3. 请求公开页面时保留服务端获取公开元数据所需的原始查询参数及顺序；仅移除 fragment。
4. 页面含公开 Open Graph 元数据或 `window.__INITIAL_STATE__` 时，Adapter 输出非空 `ImportContent`，后续进入 LLM 生成或草稿确认。
5. 页面确实需要登录、无公开内容、网络失败、HTTP 异常或结构变化时，任务保存稳定错误码和可操作降级提示。
6. 任务已经持久化为 `failed` 且包含具体错误时，进度页优先显示该任务错误，不再叠加页面级“当前操作未完成”。
7. 请求、错误和日志不得泄漏分享查询参数、Cookie、Authorization、API Key、完整页面正文、完整 Prompt 或完整模型响应。

## 3. 已实现

### 3.1 小红书 PC webshare 页面解析

- 支持从页面脚本解析 `window.__INITIAL_STATE__ = {...}`。
- 使用平衡花括号扫描完整 JSON 对象，避免嵌套对象被正则过早截断。
- 支持真实页面中的 `noteData.data.noteData` 路径。
- 将字符串外的 JavaScript 裸 `undefined` 安全转换为 JSON `null`，同时保留字符串正文中的 `"undefined"`。
- 提取笔记标题、描述、作者、发布时间和 `imageList`。
- 图片兼容字段包括 `urlDefault`、`urlPre`、`url`、`urlList`、`urls`、`infoList`、`urlSizeLarge`、`urlSizeMedium` 和 `urlSizeSmall`。
- 每个图片条目按优先级选择第一个可用 URL，并进行精确 URL 去重。
- 在小红书域名下，不再把通用站点标题“小红书”或 `Xiaohongshu` 当作笔记标题。

### 3.2 请求兼容与安全边界

- 小红书 Adapter 使用固定 Android Mobile Chrome User-Agent。
- 请求增加 `Accept-Language: zh-CN,zh;q=0.9,en;q=0.8`。
- 保留原始查询字符串及顺序，只移除 fragment。
- 不发送 Cookie 或 Authorization。
- 页面宿主刷新回调异常不再覆盖持久化任务结果。

### 3.3 导入启动前错误可观测性

- `AiRecipeBackendFacade.runImportTask()` 将能力校验、会话读取、Runner 创建和 Runner 执行统一放入同一异常映射边界。
- 自定义 LLM 未配置、配置不可读、离线、会话或导入设置读取失败、能力状态读取失败均转换为稳定脱敏文案。
- 导入进度页在任务已经持久化为 `failed` 且 `errorMessage` 非空时，优先显示任务错误，不再同时显示页面级通用错误。
- 已补充 Facade 和 Widget 测试定义，覆盖前置异常映射以及“持久化任务错误优先于页面运行异常”。

### 3.4 LLM 响应兼容与严格 Schema 加固

- 生成 Prompt 明确根对象、所有嵌套字段的类型约束和受控枚举，并提供一份完整合法 JSON 示例。
- 响应解析支持纯 JSON、唯一 `json`/空语言 fenced block、唯一 JSON 外的普通说明，以及完整闭合的 `<think>...</think>` 前缀。
- JSON 对象提取按字符串、转义和花括号层级扫描，不会把正文字符串中的花括号误认为对象边界。
- 多个 JSON 对象、多个 fence、截断或不平衡对象、未闭合 fence/推理包装继续拒绝，不能为了兼容而猜选其中一个对象。
- Recipe 字段 Schema 保持严格：未知字段和错误字段类型不被静默接受。
- OpenAI-compatible Provider 将 `finish_reason == length` 和空白 content 识别为无效响应；不会把截断内容交给 Schema 猜测解析。
- 不向兼容性未知的第三方服务强制发送 `response_format`，避免服务端协议差异阻断普通 Chat Completions。
- 已补充 Prompt、解析器和 Provider 测试定义；按 `ADR-0015` 未由 Codex 执行。

### 9.2 定位结论

- 持久化错误 `The public page did not expose usable text or media.` 只可能来自 `PublicPageImportContentAdapter.fetch` 的“无文本且无媒体”判空分支（`invalidPayload`，不可重试）。
- 代码路径确认：fetch 在推进到 `extracting` 之前执行，判空失败时任务以 `fetching` 阶段失败；项目负责人观察到的“生成结构化”阶段与持久化错误不一致，属于 UI 观察时序/时间线标签歧义，不再以此猜测根因。
- 环境研究（非 App 内请求）确认：无完整分享参数（`xsec_token`）的 `https://www.xiaohongshu.com/explore/6a421c6b00000000170297f9` 被平台返回推荐 feed 页，正文不含目标笔记 ID `6a421c6b`，解析器对这类页面合法地提取不到任何文本或媒体。

### 9.3 已实施修复（ADR-0016）

- 判空分支改为分类：先提取目标笔记 ID（请求后 `resolvedUri`，回退到规范化链接），再判断响应是否包含该 ID：
  - 包含：`invalidPayload`，不可重试，文案“已获取到该笔记页面，但暂时无法提取有效内容。请稍后重试，或使用“粘贴正文”等方式继续整理。”
  - 不包含：`contentUnavailable`，可重试，文案“未获取到目标笔记内容。链接可能已失效、需要登录，或平台临时限制了访问；请检查链接后重试，或使用“粘贴正文”等方式继续整理。”
- 页面状态标记扩展：登录墙（需要登录等）、内容不可用（笔记不存在/已删除等）、风控/限流（安全验证、拖动滑块、captcha、访问过于频繁等），分别映射 `authorizationRequired` / `contentUnavailable` / `networkUnavailable`（可重试）。
- 更新 Adapter 测试定义：无内容且不含目标 ID、无内容但含目标 ID、风控标记页三个用例；产品文档 5.3.7 已补充错误文案要求。
- 未运行测试、分析器、格式化、构建、模拟器、真机或真实网络/API 请求（`ADR-0015`）。

## 11. 2026-08-02 调试摘要根因确认与 /404 安全页识别

### 11.1 项目负责人回传的调试摘要

```text
[调试] finalHost=www.xiaohongshu.com finalPath=/404/sec_AkEqEBfZ status=200
type=text/html; charset=utf-8 size=21677 initState=true noteData=4 meta=12
ogTitle=false ogImage=false ldjson=0 title=小红书
targetId=6a421c6b00000000170297f9 hasTarget=true
```

### 11.2 根因确认

- `finalPath=/404/sec_AkEqEBfZ`：请求被小红书安全机制重定向到 `/404/` 安全验证页，`sec_` 前缀是风控令牌；页面以 HTTP 200 返回，但内容是验证/失效壳页。
- 页面只有通用站点标题“小红书”、无 `og:title`/`og:image`、无 JSON-LD，因此解析器提取不到任何文本或媒体——**不是解析器缺陷，而是请求未到达目标笔记页**。
- `hasTarget=true` 只是因为 404 壳页正文引用了目标 noteId，不能作为“已获取目标页”的依据。
- 该链接在更早版本能进入 65%（fetch 成功），说明笔记存在，当前被拦截属于平台安全验证/风控，通常是临时的。

### 11.3 已实施修复

- 新增 `_throwForSecurityOrNotFound`：`resolvedUri.path` 为 `/404` 或 `/404/...` 时映射为 `networkUnavailable`（可重试），文案“平台未返回笔记内容（可能正在执行安全验证，或笔记已失效）。请稍后重试，或改用完整分享链接、粘贴正文等方式继续整理。”
- 该检测在 HTTP 状态与判空之前执行，避免 404 壳页被误判为“已获取目标页但无法提取”。
- 调试摘要补充 `redirect` 重定向计数；`debugPrint` 输出不变，不进入用户可见错误消息。
- 新增测试定义：`/404/sec_` 页映射为可重试 `networkUnavailable`；未运行测试、分析器、构建或真实网络请求（`ADR-0015`）。
