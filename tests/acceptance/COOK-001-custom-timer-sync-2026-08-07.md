# COOK-001 烹饪模式无时长步骤自定义计时并同步菜谱验收

> 日期：2026-08-07
> 状态：VERIFY（等待项目负责人复测）
> 关联：`tracking/BACKLOG.md`（COOK-001）、`tracking/CHANGELOG.md`（2026-08-07）、
> `tracking/DECISIONS.md`（ADR-0037）、`docs/product/AI食谱应用产品需求文档.md` 5.4.4

## 背景与目标

项目负责人反馈：**烹饪界面里有一些步骤没有计时，希望加一个自定义的；如果用户
自定义了，也请同步到菜谱中。**

现状：菜谱步骤的 `durationSeconds` 是可空字段，无时长步骤在烹饪模式只显示
「本步骤未设置时长」的静态提示，无法启动计时器；用户每次下厨都只能干等。

本轮实现：

1. **自定义计时入口**：无时长（`durationSeconds` 为 null 或 0）步骤显示
   「自定义本步计时」按钮，点击弹出像素风分钟/秒输入弹窗。
2. **同步到菜谱**：确认后先调用领域新增的 `updateRecipeStepDuration` 把时长写入
   菜谱步骤（只重建目标步骤、保留其他字段、递增 `localVersion`），再创建
   「步骤 N」计时器；下次进入该菜谱烹饪时可一键启动，无需重新输入。
3. **弹窗校验**：分钟/秒非数字或总秒数 ≤ 0 时提示「请输入大于 0 的时长」且不关闭
   弹窗；取消不产生任何副作用。

## 前置条件

1. 重新构建并安装 Android 版本（本功能无数据库结构变化，可直接覆盖安装）。
2. 准备一份**包含无时长步骤**的菜谱：
   - 方案 A：手动创建菜谱，在步骤编辑中留一个步骤不填时长。
   - 方案 B：AI 导入后检查草稿/正式菜谱中是否有 `durationSeconds` 为空的步骤。
   - 若无现成无时长步骤，可编辑已有菜谱删除某一步骤的时长保存后使用。
3. 进入烹饪模式：菜谱详情页 → 「开始烹饪」。

## 复测用例

### 用例 1：无时长步骤显示「自定义本步计时」按钮

**步骤**：进入烹饪模式，滑动到无时长（未设置时长）的步骤。

**预期结果**：

- 该步骤显示「自定义本步计时」按钮（时钟图标）。
- 该步骤**不显示**「启动计时器」一键按钮（有别于有时长步骤）。
- 计时器列表为空时**不显示**「暂无计时器…」类提示文案。
- 无时长步骤**不显示**「本步骤未设置时长…」类提示文案。
- 有时长的步骤仍保持原「启动计时器」一键行为。

**回传**：无时长步骤与有时长步骤各一张截图。

### 用例 2：自定义 2 分 30 秒并同步到菜谱

**步骤**：在无时长步骤点「自定义本步计时」→ 分钟填 `2`、秒填 `30` → 点「开始计时」。

**预期结果**：

- 弹窗关闭，创建标签为「步骤 N」（N 为该步骤序号）的计时器，剩余时间约 2:30。
- 出现 SnackBar「已创建计时器，并将时长同步到菜谱。」。
- 返回菜谱详情再进入烹饪模式（或同页直接看）：该步骤现在显示「启动计时器」
  一键按钮，点击后直接以 2:30 启动，无需再次输入。

**回传**：计时器创建后的截图 + 再次进入烹饪模式该步骤的截图（证明时长已持久化）。

### 用例 3：自定义时长重启后仍保留（持久化）

**步骤**：完成用例 2 后，强制停止 App 并重新打开 → 进入该菜谱烹饪模式。

**预期结果**：

- 该步骤仍显示「启动计时器」且时长为上次自定义值（2:30），无需重新输入。
- 菜谱详情/编辑页中该步骤时长已更新。

**回传**：重启后该步骤截图（可选编辑页时长截图）。

### 用例 4：非法输入被拦截

**步骤**：在无时长步骤点「自定义本步计时」→ 分钟/秒都填 `0`（或填非数字）→
点「开始计时」。

**预期结果**：

- 弹窗**不关闭**，出现提示「请输入大于 0 的时长」。
- 不创建计时器、不修改菜谱。

**回传**：提示截图。

### 用例 5：取消无副作用

**步骤**：在无时长步骤点「自定义本步计时」→ 分钟填 `3` → 点「取消」。

**预期结果**：

- 弹窗关闭。
- **不创建**任何计时器。
- 该步骤仍显示「自定义本步计时」，菜谱步骤时长仍为空（重启后验证也可）。

**回传**：取消后该步骤截图。

### 用例 6：小屏幕 / 长步骤下的弹窗可用性（可选）

**步骤**：在步骤描述较长的无时长步骤上打开「自定义本步计时」弹窗，并尝试在
小字号系统设置下输入。

**预期结果**：

- 弹窗完整可见、可输入、可确认/取消，无控件遮挡或溢出。

**回传**：弹窗截图（如条件允许）。

## 追加：烹饪模式整屏空白回归验证（2026-08-11）

**背景**：修复进入烹饪模式后整屏空白（`_CookingPixelSurface` 的 `StackFit.expand` 在步骤 `ListView` 无限高度下抛 `infinite height`；已改为无限高度时用 `StackFit.loose`，并给 ListView 内 `Column` 加 `mainAxisSize: min`）。

**前置条件**：至少一个含烹饪步骤的菜谱，和一个不含步骤的菜谱。

**操作步骤**：
1. `flutter run`（debug）进入一个含步骤的菜谱 → 点「开始烹饪」。
2. 观察：应显示顶部步骤进度头、步骤卡（详细步骤 + 所需信息 + 所需食材）、计时器区与底部「上一步 / 下一步」导航；无红色报错、无空白。
3. 若有步骤无时长 → 出现「自定义本步计时」按钮；有时长 → 出现「启动本步计时」按钮。
4. 切换上一步 / 下一步，确认步骤卡正常更新、无 `infinite height` 异常。
5. 进入一个无步骤的菜谱 → 应显示「尚未添加烹饪步骤」空状态，而非空白。
6. 给当前步骤启动一个计时器，确认计时卡正常渲染并倒计时。

**预期结果**：
- 所有场景均不再出现 `BoxConstraints forces an infinite height`；页面内容完整可见。
- 底部导航按钮、步骤卡、计时卡在 debug 下无布局报错。

**回传**：各步骤的截图 + `flutter run` 控制台是否有异常。`通过 / 不通过`。
