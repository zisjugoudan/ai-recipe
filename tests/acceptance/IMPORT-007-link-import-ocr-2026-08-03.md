# IMPORT-007：链接导入启用本地 OCR——图片与正文整合后交给 AI 生成菜谱

> 日期：2026-08-03
> 状态：`VERIFY`（Android 已实现，等待项目负责人复测；iOS 未验证）
> 平台：Android
> 关联：`OCR-001`、`OCR-002`、`BUG-003`、`IMPORT-004`、`ADR-0017`

## 1. 用户价值

小红书/抖音图文笔记导入时，配图里的菜谱信息不再被丢弃：本地 OCR 可用时，图片自动识别成文字，与页面正文按顺序合并为同一批证据后统一交给 AI，生成更完整的菜谱草稿。

## 2. 已实现

- `AiRecipeBackendFacade.runImportTask` / `dispatchPendingImports` 的执行计划参数改为可空；为 null 时读取 `AppCapability.localOcr` 能力快照自动解析：
  - OCR 就绪 → `ImportExecutionPlan(llm: custom, ocr: local)`；
  - OCR 未就绪或快照不可读 → 纯文本路径（`ocr: disabled`）。
- OCR 阶段复用既有 `OcrEnrichingImportContentProcessor` + `RemoteStagingOcrProvider`：远程图片经 OCR-002 安全暂存后由本地 OCR 识别，OCR 文本片段与页面正文片段按 `order` 合并进同一 `ImportContent.textFragments`，再统一交给 `LlmRecipeGenerationProcessor`。
- 回退语义：OCR 未安装时，有正文的图文内容仍可纯文本生成；只有图片无正文的内容失败并提示“需要先完成图片文字识别”。
- 无图（纯文字）内容不触发 OCR。
- OCR 链路错误文案中文化（模型未安装、识别不可用、图片无效、网络/超时等固定中文），不再透传底层英文。
- 已新增测试定义（未运行）：Facade 自动启用/降级/纯图片失败、OCR 装饰器稳定中文错误映射。

## 3. 已知限制

- 真实 PP-OCRv5 模型质量、性能与准确率仍未验证（`SPK-002`）。
- 本地 OCR 模型需先在“我的 → OCR 引擎”安装并启用；未安装时纯图片内容无法生成。
- 视频 ASR 仍不可用（`managedAsrBuilder` 未接入），含视频的图文内容按既有路径处理。

## 4. Android 人工复测步骤

### 4.1 前置条件

1. 安装包含 `IMPORT-007` 的 Android 构建。
2. 在“我的 → OCR 引擎”确认本地 OCR 模型已安装并显示“就绪”（或按 4.2 的降级分支测试）。
3. 在“自定义 LLM API”确认自有 AI 服务已配置且可连接。
4. 准备一个可访问的小红书/抖音图文链接（建议带完整分享参数）。

### 4.2 操作步骤（OCR 已安装分支）

1. 首页进入“快速导入 → 粘贴链接”，粘贴图文笔记链接并确认。
2. 观察导入进度页：确认经过“正在获取公开内容”→ 图片识别（OCR）→“正在生成结构化菜谱”。
3. 进入草稿确认页：确认生成的草稿来自正文与图片识别的整合结果（菜名、食材、步骤完整）。
4. 打开“原文证据”查看区：确认存在页面文本与 OCR 文本两类证据。
5. 保存草稿为正式菜谱，确认首页未完成数量减少、重启后可打开。

### 4.3 操作步骤（OCR 未安装降级分支）

1. 卸载或未安装本地 OCR 模型，粘贴一条“有正文的图文链接”。
2. 确认仍可基于正文生成草稿（不因 OCR 未装而整体失败）。
3. 粘贴一条“只有图片、没有正文”的链接（或使用仅含图片的样本），确认失败提示为“当前内容需要先完成图片文字识别”之类中文文案，并引导安装 OCR。
4. 粘贴一条纯文字链接，确认全程不进入图片识别阶段。

### 4.4 错误路径

1. 本地 OCR 模型未安装时触发图片识别，确认错误文案为中文（如“本地 OCR 模型尚未安装，请先在 OCR 设置中安装模型包。”）。
2. 断网或图片地址不可访问时触发识别，确认文案为“无法获取图片内容，请检查网络后重试。”之类中文提示。
3. 全程检查失败页是否出现底层英文错误文本。

### 4.5 预期结果

- OCR 就绪时图文内容自动走 OCR 并整合进 AI 输入，草稿更完整；OCR 未就绪时按降级路径表现稳定，所有用户可见错误为中文可操作文案。
