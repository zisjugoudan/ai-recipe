# 人工验收与测试方法

本目录是任务测试方法和项目负责人实际验收结果的事实源。

## 文件命名

每个任务或用户故事使用独立文件，例如：

```text
BUG-004-unfinished-import-resume-2026-08-02.md
US-004-link-import-YYYY-MM-DD.md
```

## Codex 的职责

实现完成后，Codex只负责准备测试方法，不默认执行测试。验收文件至少应包含：

1. 任务目标和本次修复说明。
2. 测试平台与前置条件。
3. 按步骤可复现的操作方法。
4. 每一步对应的预期结果。
5. 需要覆盖的正常、加载、错误、恢复、取消、极限或离线状态。
6. 用户可直接复制填写的结果回传模板。
7. 截图、录屏、Logcat 或错误文字等证据要求。
8. 明确写出“Codex 未执行测试”和当前任务状态 `VERIFY`。

静态代码阅读、差异检查和编译逻辑推断只能写为“静态复核”，不能写为“测试通过”。

## 项目负责人的职责

项目负责人按照验收文件在指定平台执行，并反馈：

- 应用版本或可识别的构建版本。
- 测试设备、系统、网络环境。
- 登录或游客模式。
- 每条验收项的“通过 / 失败 / 未执行”。
- 失败时的实际页面、数量变化、完整错误文字和复现步骤。
- 可提供时附截图、录屏或 Logcat 的本地路径。

现阶段默认由项目负责人在 Android 模拟器执行；未实际测试的 iOS 项必须写为“未验证”，不得从 Android 结果推断。

## Codex 收到反馈后的归档职责

1. 将项目负责人的原始结果整理到对应验收文件，区分“预期结果”和“实际结果”。
2. 涉及链接解析、OCR、ASR 或 LLM 时，同步 `tests/ai-quality/AI_QUALITY_LOG.md`。
3. 更新 `tracking/BACKLOG.md`、`tracking/CURRENT.md` 和 `tracking/CHANGELOG.md`。
4. 全部验收标准满足时转为 `DONE`；存在缺陷时转回 `DOING` 并记录根因；信息不足时继续保持 `VERIFY`。
5. 不删除或改写项目负责人提供的失败事实，不使用未执行的测试填充“通过”。
