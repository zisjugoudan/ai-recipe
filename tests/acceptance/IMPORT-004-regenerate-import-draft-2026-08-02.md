# IMPORT-004：待确认草稿重新生成 Android 验收方法

> 日期：2026-08-02  
> 状态：`VERIFY`（Android 已实现，等待项目负责人复测；iOS 未验证）  
> 平台：Android  
> 关联：`AI-002`、`IMPORT-001`、`IMPORT-002`、`APPLICATION_BACKEND_FACADE.md`

## 1. 用户价值

AI 生成的菜谱草稿不理想时，用户可以在草稿确认页点击“重新生成”，使用同一原文再次交给 AI 整理，避免放弃草稿后重新导入。

## 2. 已实现

- 草稿确认页新增“重新生成”卡片与按钮（Key `regenerateImportDraftButton`）。
- 点击后弹二次确认（Key `confirmRegenerateImportDraftButton`），确认后按钮禁用并显示“正在重新生成…”。
- 重新生成复用本次会话内保存的原文证据（`ImportContent`），通过 `AiRecipeBackendFacade.regenerateImportDraft` → `ImportTaskRunner.regenerateWithContent` 重新执行 LLM Processor，不重新抓取、不重新 OCR/ASR。
- 成功：任务 `resultRecipeId` 指向新草稿（新增 `ImportTask.reassignResultRecipe` 领域方法与 `ReassignImportTaskRecipe` use case），旧草稿走安全丢弃器 best-effort 清理，任务保持 `needsReview`，页面重建表单。
- 失败：任务保持 `needsReview`、旧草稿保留，页面显示稳定脱敏错误。
- 无会话证据（例如 App 重启后进入草稿确认页）：按钮禁用并显示“原始内容已过期，无法重新生成”。
- 已新增测试定义：Runner 成功替换/状态校验/失败保留、Widget 禁用态与确认流程（未运行）。

## 3. 已知限制

- 会话原文证据只在本次会话内传递（既有限制）；App 重启后进入草稿确认页无法重新生成，按钮禁用。
- 重新生成期间不支持用户取消；不限制生成次数。
- 需要重新 OCR/ASR 的场景不支持（走放弃草稿后重新导入）。

## 4. Android 人工复测步骤

### 4.1 前置条件

1. 安装包含 `IMPORT-004` 的 Android 构建。
2. 在 LLM 设置页确认 API Base URL、API Key 和模型已保存且连接测试通过。
3. 使用一个可成功生成草稿的公开链接（或粘贴正文降级）完成一次导入，进入草稿确认页。
4. 回传截图与文案不得包含 API Key、Authorization、完整分享链接查询参数或完整模型响应。

### 4.2 操作步骤

1. 进入草稿确认页，确认顶部出现“重新生成”卡片与按钮。
2. 点击“重新生成”，确认出现“重新生成这份 AI 草稿？”确认框。
3. 点“确认重新生成”，确认按钮变为“正在重新生成…”且不可重复点击。
4. 等待完成：成功后表单内容替换为新草稿；观察新草稿与旧草稿是否明显不同。
5. 重新生成后直接点击“保存菜谱”，确认任务完成、正式菜谱可打开、首页未完成数量减少；强制停止并重启 App 后正式菜谱仍可恢复。
6. 再次完成一次导入进入草稿确认页，先对草稿做任意编辑，再点“重新生成”并确认，观察编辑内容是否被替换。
7. 强停重启 App，从首页“未完成的导入”重新进入同一草稿确认页，确认“重新生成”按钮禁用并显示“原始内容已过期，无法重新生成”。
8. 若无 LLM 配置，另开一次导入进入草稿确认页点“重新生成”，确认显示稳定错误且旧草稿、任务状态不变。

### 4.3 预期结果

- 按钮存在、可点；无会话证据时禁用并提示。
- 确认后 busy 防重复；成功后表单刷新为新草稿，任务保持待确认。
- 重新生成后保存菜谱：任务 `completed`、正式菜谱可打开、首页数量减少、重启可恢复。
- 失败：旧草稿保留、任务仍待确认、显示稳定脱敏错误、无多余草稿或重复任务。
- 全程不创建重复任务；不显示完整模型响应或敏感配置。
