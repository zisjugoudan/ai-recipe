# BUG-005：失败导入主动结束 Android 验收方法

> 日期：2026-08-02  
> 状态：`DONE`（Android 已验收，iOS 未验证）  
> 平台：Android（iOS 未验证）  
> 关联：`BUG-003`、`IMPORT-001`、`BUG-004`

## 1. 问题

不可重试的导入任务失败后仍合理地计入首页“未完成的导入”，但失败页没有可用的结束操作。用户返回首页后会持续看到该任务，现有恢复入口又无法让不可重试失败继续执行。

本任务不通过过滤 `failed` 隐藏问题，而是让用户在查看真实错误后主动把任务转换为 `cancelled`。

## 2. 预期实现

- failed 页面保留错误标题、稳定错误文案和人工粘贴正文、图片/OCR、视频、手动创建入口。
- failed 页面显示“结束此导入”。
- 点击期间按钮禁用并显示“正在结束…”。
- 操作复用持久化 `failed → cancelled`，结束后页面显示“解析已取消”。
- cancelled 不计入首页未完成数量；failed 在用户处理前继续计入。
- 可重试失败继续保留重试入口；queued/running 的“取消解析”不退化。
- 不删除失败记录，不创建重复任务、草稿或正式菜谱。

## 3. 已实现

- failed 页面新增稳定控件标识 `dismissFailedImportButton`，文案为“结束此导入”。
- 提交期间按钮禁用并显示“正在结束…”，防止重复操作。
- 页面复用原任务 ID 调用 `cancelImportTask(taskId)`，不创建替代任务。
- 后端将 `failed` 持久化为 `cancelled`；成功后页面应用返回的取消快照并刷新首页宿主数据。
- 可重试 failed 继续保留既有“重新解析”入口；不可重试 failed 不再显示无效恢复入口。
- queued/running 原“取消解析”行为保持；cancelled 页面不再显示结束、重试或运行中取消按钮。
- 已补充 Widget 测试定义；按 `ADR-0015` 未由 Codex 执行。
- 2026-08-02 独立静态审查覆盖领域状态转换、CAS 持久化、Facade、草稿清理保护、页面按钮状态和首页刷新链路，未发现阻断问题；该结论不替代 Android 人工复测。

## 4. Android 人工复测步骤

### 4.1 前置条件

1. 安装包含 `BUG-005` 修复的 Android 构建。
2. 准备一个状态为 failed 的不可重试导入任务；可直接使用 `BUG-003` 产生的 65% Schema 失败任务。
3. 记录首页操作前“未完成的导入”数量 N。
4. 截图和反馈不得包含 API Key、Token、Cookie、Authorization 或完整带查询参数的分享 URL。

### 4.2 操作

1. 点击首页未完成提示，确认打开原失败任务，不创建新任务。
2. 确认失败页仍显示原错误和人工降级入口。
3. 确认页面存在“结束此导入”。
4. 点击该按钮，观察是否立即变成“正在结束…”且不可重复点击。
5. 等待页面显示“解析已取消”。
6. 返回首页，记录未完成数量。
7. 再次点击未完成提示，确认不会重新打开已经结束的任务。
8. 强制停止并重启 App，再次检查未完成数量和任务恢复行为。
9. 另行确认一个 queued/running 任务仍可使用“取消解析”；若有可重试失败任务，确认其重试入口仍存在。

### 4.3 预期

- 首页数量从 N 减少为 N-1。
- 强停重启后仍为 N-1，已结束任务不再作为未完成恢复。
- 原任务持久化状态为 cancelled，页面终态为“解析已取消”。
- 不出现重复任务、多余草稿或正式菜谱。
- queued/running 取消能力和可重试失败入口不退化。
