# IMPORT-005：菜谱多封面图与详情页轮播 Android 验收方法

> 日期：2026-08-02  
> 状态：`VERIFY`（Android 已实现，等待项目负责人复测；iOS 未验证）  
> 平台：Android  
> 关联：`APP-001`、`APP-004`、`UI-001`

## 1. 用户价值

用户可给菜谱添加多张封面图，从系统相册一次多选；图片复制到应用私有目录持久化，详情页顶部以轮播展示。

## 2. 已实现

- 数据层：`Recipe.images`（多图本地路径列表）；SQLite 升级到 v4，新增 `recipe_images(recipe_id, image_path, sort_order)`；Repository 读写与永久删除级联。
- 存储：新增 `DeviceRecipeCoverImageStager`，把来源图片复制到 `<documents>/recipe_covers/<containerId>/<index>.<ext>`，校验空文件、20MB 上限、扩展名白名单，容器 ID 防路径注入；提供单文件/整组清理。
- Facade：`stageCoverImages(containerId, sourcePaths)`、`deleteCoverImage(imagePath)`。
- 编辑页：新增“封面图片”分区，支持相册多选（扩展 `ImportImagePicker.pickMultipleImages`）、缩略图网格、首图“封面”徽标、逐张删除（同步清理文件）；保存时 `RecipeDraftInput.images` 写入；首图同时作为 `coverImage`。
- 详情页：`_RecipeHero` 有图时用 PageView 轮播 + 指示点，无图回退原像素插画。
- 副本行为：`copyRecipe` 不复制封面图片文件（避免共享文件误删，副本封面为空）。
- 已新增测试定义：编辑页封面区空态/已有图渲染、stager 复制/校验/清理（未运行）。

## 3. 已知限制

- 新建菜谱在保存前复制使用临时容器 ID，保存失败可能遗留孤儿图片文件（best-effort 容忍）。
- 相册多选在部分设备/系统版本可能退化为单选或受系统限制。
- 导入图文自动带多张封面图由 `IMPORT-006` 覆盖，当前导入草稿仅保留首图。

## 4. Android 人工复测步骤

### 4.1 前置条件

1. 安装包含 `IMPORT-005` 的 Android 构建。
2. 准备 2～3 张相册图片。

### 4.2 操作步骤

1. 新建菜谱，确认出现“封面图片”分区与“添加封面图（可多选）”。
2. 点击添加，一次选择 2～3 张图片；确认缩略图立即出现、首张带“封面”标记。
3. 删除中间一张，确认缩略图消失。
4. 填写菜名并保存，进入详情页，确认顶部以轮播展示剩余封面图、可左右滑动、多图有指示点。
5. 强停并重启 App，重新打开该菜谱，确认封面图仍显示。
6. 编辑该菜谱，删除一张并保存；确认详情页同步变化、对应私有文件被清理。
7. 复制该菜谱，确认副本无封面；删除副本后源菜谱封面不受影响。
8. 尝试选择空文件或超大图片（如超过 20MB），确认出现稳定错误且不中断保存。

### 4.3 预期结果

- 多选、缩略图、删除、保存、轮播、重启恢复、副本隔离均正常；无图菜谱保持像素插画。
- 私有文件随删除清理；错误路径稳定脱敏。
