# IMPORT-006：链接导入自动获取公开内容配图作为菜谱封面

> 日期：2026-08-03
> 状态：`VERIFY`（Android 已实现，等待项目负责人复测；iOS 未验证）
> 平台：Android
> 关联：`IMPORT-005`、`OCR-002`、`BUG-003`、`IMPORT-007`

## 1. 用户价值

从链接添加菜谱时，如果小红书/抖音笔记带有图片，应用自动把配图下载到本地并作为菜谱封面（轮播展示），不需要用户手动重新选图，图片在应用重启后仍可用。

## 2. 已实现

- 新增领域接口 `RecipeCoverImageStorer`（`copyIn`/`deleteFile`/`deleteContainer`），`DeviceRecipeCoverImageStager` 实现（私有目录 `recipe_covers/<containerId>/`）。
- `LlmRecipeGenerationProcessor` 生成草稿时，把 `ImportContent.media` 中带远程地址的图片经 OCR-002 安全暂存下载并校验后复制到 `recipe_covers/<recipeId>/<index>.<ext>`，写入草稿 `images`/`coverImage`（首图即封面）；最多 9 张。
- 失败语义：单张图片下载或落盘失败 best-effort 跳过；全部失败时草稿仍生成（无本地封面，回退原占位行为），不阻塞导入。
- 组合根装配：链接导入（含 OCR 自动启用的 IMPORT-007 路径）的 LLM 处理器注入封面存储与远程暂存。
- 孤儿清理：`SafeImportRecipeDraftDiscarder` 删除草稿（放弃/取消/重新生成替换）时同步删除该草稿的封面目录。
- 已新增测试定义（未运行）：处理器封面落盘/下载失败降级/无图跳过，Facade 集成草稿本地封面。

## 3. 已知限制

- 下载依赖平台 CDN 可达性与网络；全部失败时草稿无本地封面（详情页回退像素插画）。
- 真实小红书 CDN 图片的格式/大小需符合安全暂存层白名单（JPEG/PNG/WebP、≤16MB）。
- 手动图片导入与粘贴正文入口不触发配图下载（无远程图片）。
- 本轮 debug 结论：CDN 允许无 Cookie 下载（Windows 同网络 curl/Dart 均 200）；真机 403 根因为 DNS 解析 IPv6 在前、客户端固定连第一个（IPv6）地址被 CDN 边缘节点拒绝，已改为 IPv4 优先 + 地址级故障转移。模拟器环境另有 `PARTIAL_CONNECTIVITY` 网络异常，不影响真机修复结论。

## 3.1 状态码采集（本轮新增，用于确认 403 vs 200）

- 已为失败日志增加 `status=` 输出：`[AIRecipe][CoverImage] 配图下载失败 ... error=OcrProviderException(invalidResponse status=XXX)`。
- 已过滤 `ci.xiaohongshu.com/?imageMogr2/...` 这类缺图片 ID 的残缺 URL，重测时不应再出现。
- 已实现 IPv4 优先 + 地址级故障转移：`[AIRecipe][RemoteImage] 已连接 <IP>` 应显示 IPv4 地址（如 `58.251.127.109`）；若某地址被拒（403）会打印 `地址 <IP> 被拒` 并尝试下一个地址。

## 4. Android 人工复测步骤

### 4.1 前置条件

1. 安装包含 `IMPORT-006` 的 Android 构建。
2. 在“自定义 LLM API”确认自有 AI 服务已配置且可连接。
3. 准备一个带多张配图的小红书/抖音链接（建议带完整分享参数）。

### 4.2 操作步骤

1. （本轮新增）在项目根目录执行 `flutter build apk --debug`（Codex 沙箱内构建会卡死，需在外部终端执行），然后 `adb install -r build/app/outputs/flutter-apk/app-debug.apk`。
2. 首页进入“快速导入 → 粘贴链接”，粘贴带配图的笔记链接并确认。
3. 等待导入完成并进入草稿确认页；若配图仍失败，执行 `adb logcat -d | grep CoverImage`，回传每张图的 `status=` 值（如 `invalidResponse status=403` / `status=200`）。
4. 确认草稿确认页顶部的封面区域展示笔记配图（多张可轮播/缩略图展示）。
5. 保存草稿为正式菜谱，进入详情页确认顶部轮播展示全部配图。
6. 强停并重启 App，重新打开该菜谱，确认封面图仍显示。
7. 对另一条链接执行导入后放弃草稿，确认应用私有目录中对应封面目录被清理（可通过文件管理器或后续重新导入同链接不残留重复图片验证）。
8. 使用一条图片下载会失败的链接（或断网后导入），确认草稿仍能生成（无封面或部分封面），不因图片失败而整体失败。

### 4.3 预期结果

- 链接导入自动带图：草稿/正式菜谱封面为笔记配图（本地持久化），重启后仍显示。
- 单张失败不阻塞整体导入；全部失败时草稿仍生成。
- 放弃/重新生成草稿后旧封面文件被清理。
