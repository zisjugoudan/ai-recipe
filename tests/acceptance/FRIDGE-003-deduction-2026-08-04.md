# FRIDGE-003：下厨后库存确认扣减

> 日期：2026-08-04
> 状态：`DOING`（代码与测试定义已完成，等待项目负责人构建 Android 复测）
> 平台：Android（iOS 未验证）
> 关联：FRIDGE-002、RECO-001、US-013、UI-016 扣减面板

## 1. 用户价值

完成烹饪后自动生成预计消耗清单，用户逐项确认/调整/换批次/取消后才更新库存并记录变更；默认选择到期更早的批次；数量未知或库存不足不产生负库存。

## 2. 已实现

- **领域**：`InventoryChange`（create/adjust/consume/usedUp/discard + confirmedByUser + relatedRecipeId）持久化到 `inventory_changes`。
- **应用**：`InventoryLibraryUseCases.consumeBatch`（数量未知拒绝自动扣减；剩余 ≤0 视为用完；不做负库存）；Facade `confirmInventoryConsumption(items)`。
- **UI**：烹饪完成（`CookingModePage` 完成确认）后自动进入扣减确认页：根据菜谱食材与库存自动生成预计消耗（按名称匹配、同名批次按到期日升序默认选最早），逐项勾选/修改数量/更换批次，底部「确认并更新冰箱」/「暂不更新」（库存保持不变，烹饪流程仍正常结束）。

## 3. Android 人工复测步骤

1. 冰箱-库存添加「番茄 2 个（08-10 到期）」和「番茄 3 个（08-20 到期）」两个批次，再添加「鸡蛋 6 枚」。
2. 打开包含番茄+鸡蛋的菜谱 → 开始烹饪 → 完成烹饪 → 自动进入扣减确认页。
3. 确认页应显示番茄/鸡蛋预计消耗；番茄默认选择 08-10（更早到期）批次，可下拉更换到 08-20 批次。
4. 修改数量、取消某项勾选 → 「确认并更新冰箱」→ 返回后库存相应扣减（番茄批次剩余减少，扣完则显示已用完，不可见）。
5. 重新完成一次烹饪 → 「暂不更新」→ 库存保持不变。
6. 数量未知的批次（如 冰糖）→ 显示"数量未知，请确认用量"，不自动扣减。
