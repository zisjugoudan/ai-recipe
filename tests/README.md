# 测试与质量目录

本目录保存测试方法、项目负责人回传的实际结果、真实样本质量数据和回归证据。

## 永久协作职责

自 `ADR-0015` 生效后，测试职责固定如下：

- Codex 默认不执行自动测试、Flutter/Dart 静态分析、Android/iOS 模拟器测试、真机测试或人工验收。
- Codex 在实现完成后，必须把可复现的测试方法写入 `tests/acceptance/`，至少包含前置条件、操作步骤、预期结果、回传格式和证据要求。
- 项目负责人负责在实际设备或模拟器中执行测试，并把结果反馈给 Codex。
- Codex 收到反馈后，负责把实际结果归档到验收记录；涉及 OCR、ASR、LLM 或平台链接解析时，同时更新 `tests/ai-quality/AI_QUALITY_LOG.md`。
- 项目负责人反馈前，任务保持 `VERIFY`，不得标记为 `DONE`，也不得把静态代码阅读写成“测试通过”。
- 只有项目负责人在当前任务中明确要求 Codex 代测时，Codex 才可以例外执行；例外范围和结果必须明确记录。
- 既有历史测试结果保留为当时事实，不追溯删除。

当前人工验证平台以项目负责人明确给出的范围为准；现阶段默认只提供 Android 测试方法，iOS 标记为未验证。

## 子目录

- `acceptance/`：每个任务的测试方法，以及项目负责人回传后的人工验收记录。
- `integration/`：API、Schema、Provider 和同步契约的测试资料或测试代码。
- `ai-quality/`：OCR、ASR、LLM 和平台导入的真实质量数据。
- `fixtures/`：经授权或可公开使用的固定测试样本及说明。

## 固定质量层级

下面列出项目需要覆盖的质量层级，但不代表 Codex 已执行；每项实际状态以对应验收记录和项目负责人反馈为准：

1. 领域模型和校验规则。
2. 本地数据库、迁移和同步逻辑。
3. Provider 契约。
4. 导入流水线集成路径。
5. Android/iOS 关键流程端到端路径。
6. 用户故事人工验收。
7. AI 真实样本质量评估。

## 完成标准

- 代码实现完成不等于任务验收完成。
- 每个任务必须先有测试方法；收到项目负责人实际结果前保持 `VERIFY`。
- 每个 `DONE` 任务必须有项目负责人反馈的验证记录。
- AI 功能必须同时记录字段准确性、低置信度表现和需要人工修改的数量。
- 平台 Adapter 必须按平台独立记录回归结果。
- 测试失败不能通过修改验收标准来掩盖；如产品需求确实变化，必须先更新长期事实源。
