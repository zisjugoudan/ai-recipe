# 用户故事与验收标准

> 本文将产品需求转换为可开发、可测试的用户故事。
> 产品行为的完整定义仍以 `AI食谱应用产品需求文档.md` 为准。
> 每个开发任务必须关联一个或多个用户故事。

## 故事地图

```text
进入应用
├── 游客使用
└── 登录与同步

建立菜谱
├── 手动创建
├── 链接导入
├── 截图/视频/文本导入
└── AI 确认与保存

管理菜谱
├── 分类与标签
├── 搜索与收藏
├── 编辑与版本
└── 备份与恢复

管理家中食材
├── 维护冰箱库存批次
├── 查看临期与过期食材
├── 根据库存匹配本地菜谱
├── 缺失食材加入购物清单
└── 下厨后确认扣减

实际下厨
├── 调整份量
├── 准备食材
├── 分步烹饪
├── 计时器
└── 制作记录

配置能力
├── 本地/自有 LLM
├── 平台托管 AI
├── 本地 OCR 插件
└── 云 OCR
```

## US-001 游客进入应用

**作为一个不想注册的用户，我可以直接进入应用并建立本地菜谱库。**

### 验收标准

- [ ] 首次启动提供“游客使用”和登录入口。
- [ ] 游客不需要手机号、微信或 Apple 账号即可进入首页。
- [ ] 游客可以创建、编辑、删除、分类、收藏和搜索本地菜谱。
- [ ] 游客数据写入本地数据库，关闭并重新打开应用后仍存在。
- [ ] 页面明确说明游客数据不会自动云端备份。
- [ ] 不使用恐吓式弹窗强迫登录。

### 异常与极限

- 本地数据库初始化失败时给出可操作的重试或数据目录说明。
- 存储空间不足时不能静默丢失编辑内容。

---

## US-002 游客登录并合并数据

**作为已经积累本地菜谱的游客，我登录后可以决定如何处理本地数据。**

### 验收标准

- [ ] 登录前显示本地菜谱、分类、购物项和冰箱库存批次数量。
- [ ] 提供“合并到云端”“暂不上传”“使用云端数据”三种路径。
- [ ] 合并前可以预览重复和冲突。
- [ ] 同一来源链接的重复菜谱不会静默覆盖。
- [ ] 冰箱同名食材的多个批次不会在合并时丢失到期日期、存放位置或数量未知状态。
- [ ] API Key 不参与普通数据合并。
- [ ] 合并中断后可以安全重试。

---

## US-003 手动创建菜谱

**作为用户，我可以不依赖 AI 或链接手动创建菜谱。**

### 验收标准

- [ ] 至少可以输入菜名、食材和步骤。
- [ ] 食材支持名称、数量、单位、分组和备注。
- [ ] 步骤支持增删、编辑和排序。
- [ ] 未完成内容可以保存为草稿。
- [ ] 保存后立即出现在本地菜谱库。
- [ ] AI 服务不可用时本功能仍完整可用。

---

## US-004 粘贴小红书或抖音链接

**作为用户，我可以粘贴分享链接并看到明确的导入处理过程。**

### 验收标准

- [ ] 应用能从分享文本中识别有效 URL。
- [ ] 能识别小红书、抖音或不支持的平台。
- [ ] 依次显示获取内容、OCR、ASR、AI 生成等实际发生的状态。
- [ ] 用户离开页面后，允许后台执行的任务不会无提示消失。
- [ ] 排队或运行中的任务始终提供“取消解析”入口；AI 请求正在执行时不得禁用该入口，只有取消状态正在提交时才允许短暂禁用并显示明确反馈。
- [ ] 取消成功后任务保持取消终态；后到的 AI 成功或错误不得覆盖取消，也不得遗留未关联草稿。
- [ ] 导入失败时显示具体阶段和可操作的降级入口。
- [ ] 原始链接和来源平台被保留。
- [ ] 首页有未完成导入时显示真实持久化任务数量；点击提示直接继续最近创建的原任务，不打开新建导入页、不创建重复任务。
- [ ] 已有任务为排队、运行中断、待确认或失败时，继续入口分别进入可继续执行、恢复执行、草稿确认或失败降级状态。
- [ ] `failed` 在用户处理前计入未完成；失败页保留真实错误，可重试失败继续显示“重新解析”，所有失败任务继续显示人工降级入口。
- [ ] 所有失败任务显示“结束此导入”；点击期间显示“正在结束…”，结束后原任务持久化为 `cancelled`，不删除失败记录。
- [ ] `cancelled` 不计入未完成；返回首页后数量减少，强制停止并重启后不得再次恢复已结束任务。
- [ ] 不得通过未完成查询过滤 `failed` 来掩盖失败，也不得因结束任务创建重复任务、草稿或正式菜谱。
- [ ] 返回首页后重新读取未完成任务数量；处理完一项后可继续进入剩余任务。

### 降级路径

- [ ] 可自动重试的失败同时显示“重新解析”和全部人工降级入口；不可自动重试的失败仍显示人工降级入口。
- [ ] 粘贴原帖正文：空文本不能提交；提交后保留原任务 ID、原始链接和来源平台，并跳过公开页面获取，直接进入 LLM 整理。
- [ ] 正文整理依赖当前可用的 LLM Provider；Provider 未配置或不可用时，保留用户已输入正文并显示可操作配置提示，不显示 API Key 或正文内容到错误日志。
- [ ] 上传截图：只有媒体选择器和可用 OCR 路由均已就绪时才允许执行；禁止上传图片时不得静默调用云端 OCR。
- [ ] 上传已保存视频：只有媒体选择器和可用 ASR 路由均已就绪时才允许执行；没有可用 ASR 时必须明确说明并提供正文或手动创建入口。
- [ ] 手动创建直接进入现有菜谱编辑页，不要求 LLM、OCR 或 ASR 可用。
- [ ] 人工降级不是公开链接 Adapter 的自动重试，不消耗 Adapter 自动重试预算；中断后不得错误地回退到公开链接抓取。
- [ ] 用户取消降级或返回后，原始链接、失败阶段和可用降级入口仍可查看。

## US-005 确认 AI 生成菜谱

**作为用户，我可以在保存前核对 AI 生成的食材和步骤。**

### 验收标准

- [ ] 显示菜名、简介、份量、食材、步骤、分类和标签。
- [ ] 所有字段可手动编辑。
- [ ] 低置信度字段有文字和视觉提示，不能只依赖颜色。
- [ ] 用户可以查看字段对应的原文、OCR 或字幕证据。
- [ ] 可以只重新生成食材或只重新生成步骤。
- [ ] AI 推测的精确用量必须被明确标识。
- [ ] 未经用户确认不会写入正式菜谱库。

---

## US-006 配置本地或自有 LLM

**作为游客或登录用户，我可以连接本地或自己购买的模型 API。**

### 验收标准

- [ ] 可以新增 OpenAI 兼容配置。
- [ ] 可以新增 Ollama 配置。
- [ ] 可以填写 Base URL、模型名称和可选 API Key。
- [ ] 保存前可以测试连接。
- [ ] 连接测试显示成功能力或具体错误。
- [ ] 可以为菜谱解析、问答、视觉理解分别选择模型。
- [ ] 密钥存储在系统安全存储中，不进入普通导出。
- [ ] 游客不能选择平台托管 AI，但能看到原因和替代方案。

---

## US-007 安装本地 OCR 插件

**作为重视隐私或不想使用云服务的用户，我可以下载本地 OCR 能力。**

### 验收标准

- [ ] 插件列表显示名称、版本、语言、体积和设备要求。
- [ ] 下载前提示存储和移动数据消耗。
- [ ] 支持下载、失败重试、更新和删除。
- [ ] 包校验失败时不能加载。
- [ ] 可以设置默认插件。
- [ ] “仅本地处理”开启后图片不会发送到云端。
- [ ] OCR 结果记录 Provider 和置信度。

---

## US-008 使用平台托管 AI

**作为登录用户，我可以在有配额时使用平台托管 AI/OCR/ASR。**

### 验收标准

- [ ] 未登录时不会偷偷发起托管 AI 请求。
- [ ] 登录用户可以查看剩余配额或限制说明。
- [ ] 配额不足时提供自有 API、本地 Provider 或稍后重试选项。
- [ ] 托管任务失败时返回统一错误而非供应商原始敏感信息。
- [ ] 用户关闭允许上传后，托管视觉/OCR 服务不可被调用。

---

## US-009 查看并管理菜谱

**作为用户，我可以快速找到并打开已经保存的菜谱。**

### 验收标准

- [ ] 首页展示最近查看、分类、收藏和全部菜谱入口。
- [ ] 支持按菜名、食材、标签和备注搜索。
- [ ] 可以调整分类并收藏菜谱。
- [ ] 删除进入回收站，不立即永久消失。
- [ ] 无菜谱、搜索无结果、图片缺失和超长标题都有明确状态。

---

## US-010 烹饪模式

**作为正在做菜的用户，我可以逐步查看操作并使用计时器。**

### 验收标准

- [ ] 一屏突出一个步骤。
- [ ] 可以前后切换步骤。
- [ ] 显示该步骤相关食材、火候和时间。
- [ ] 含时间的步骤可以一键启动计时器。
- [ ] 多计时器可以并存并明确区分。
- [ ] 计时完成有本地通知。
- [ ] 大字体、系统字体缩放和高对比度可用。
- [ ] 无网络时仍能使用已保存菜谱和计时器。

---

## US-011 管理冰箱库存

**作为用户，我可以记录家中现有食材，并清楚区分不同批次、存放位置和到期状态。**

### 验收标准

- [ ] 游客和登录用户都可以在本地离线新增、编辑和删除库存批次。
- [ ] 每个批次支持食材名称、可选数量、可选单位、分类、存放位置、可选购买日期、可选到期日期和备注。
- [ ] 冰箱首页默认按冷藏区、冷冻区、常温区和其他区分区展示，并能在每个区域直接添加食材。
- [ ] 同名食材可以存在多个批次，底层数据不会被界面聚合静默合并。
- [ ] 用户可以标记用完或丢弃，并能区分正常、临期、已过期、未设置日期和数量未知。
- [ ] 临期默认定义为到期日前 3 天。
- [ ] 可以按全部、临期、已过期、冷藏、冷冻、常温和其他筛选。
- [ ] 空库存、空分区、超长名称、大量批次、无日期和无数量都有明确状态。
- [ ] 长按但未完成移动、拖拽开始、经过候选区域、无效释放和同区排序均不播放冷冻/解冻动画。
- [ ] 食材从非冷冻区进入冷冻区时，只有最终目标区接收、库存保存成功且目标食材已显示后，才在目标位置播放一次二维小格逐个出现的冷冻动画；移出冷冻区时按相反顺序逐格消失。
- [ ] 冷藏、常温和其他区之间移动不播放颜色动画；保存失败恢复原位置且不播放成功动画。
- [ ] 同名多批次、快速连续拖动、筛选或页面重建不会串动画、重复播放旧动画。
- [ ] 系统启用减少动态时直接显示最终视觉状态，不播放逐格过程。

### 异常与极限

- 已过期批次默认不参与“可用食材”推荐，但仍可查看、编辑或处理。
- 删除、标记用完和标记丢弃不得影响同名的其他批次。

---

## US-012 根据库存查找可做菜谱

**作为用户，我可以根据冰箱里已有的食材快速找到现在能做或只差少量食材的本地菜谱。**

### 验收标准

- [ ] 推荐只读取本地正式菜谱，不包含草稿和回收站。
- [ ] 无网络、未登录和没有可用 LLM Provider 时，本地推荐仍可使用。
- [ ] 推荐前用户可以从冰箱中选择本次想优先使用的一个或多个食材，并可快捷选择全部、临期食材或某个分区。
- [ ] 推荐页区分“已具备 / 现在就能做”“缺 1 样”“缺 2 样”“优先清库存”，缺失超过 2 样默认收起为更多缺失。
- [ ] 推荐卡片展示已选命中、冰箱已有但未选择、缺失项、匹配食材数、主要必需食材总数、临期食材、推荐原因、时间和难度。
- [ ] 当冰箱有西红柿和鸡蛋但用户只选择西红柿时，可以推荐“西红柿炒鸡蛋”，并标注鸡蛋是冰箱已有但未选择；如果冰箱没有鸡蛋，则标注缺 1 样：鸡蛋。
- [ ] 基础调味品可标记为常备，不计入主要缺失数。
- [ ] 数量为空或单位无法换算时显示“有该食材，数量是否足够需确认”，不得宣称一定够用。
- [ ] 默认按缺失食材更少、使用临期食材更多、匹配比例更高排序。
- [ ] 缺失食材可以加入购物清单。
- [ ] 可以从推荐进入菜谱详情或开始烹饪。

### 异常与极限

- 无库存时引导先添加食材，不展示虚假的推荐结果。
- 无匹配菜谱时允许查看缺失较多的本地菜谱或继续添加库存，但不自动调用 AI。
- 中文同义词、标准化和单位换算以 `SPK-008` 验证结果为准。

---

## US-013 下厨后确认扣减库存

**作为完成一道菜的用户，我可以确认实际使用了哪些库存食材，再更新冰箱。**

### 验收标准

- [ ] 完成烹饪后自动生成预计消耗清单，但不直接扣减库存。
- [ ] 用户可以逐项确认、调整数量、更换目标批次或取消。
- [ ] 同名多批次默认选择到期更早的批次，但提交前可查看和修改。
- [ ] 只有用户确认后才更新库存并写入变更记录。
- [ ] 取消或关闭确认面板后库存保持不变。
- [ ] 数量未知、单位不可换算或库存不足时要求用户确认，不产生负库存。

---

## US-014 全量备份并恢复菜谱库

**作为重视本地数据的用户，我可以把当前设备的全部菜谱保存为一个可迁移文件，并在本机或另一台受支持设备上安全恢复。**

### 验收标准

- [ ] 游客、登录用户和离线状态都可以创建和恢复本地全量备份，不以云同步或可用 AI Provider 为前置条件。
- [ ] 创建备份时覆盖全部正式、草稿、归档和回收站菜谱，以及分类、分类关系、食材、步骤、标签、收藏、时间/版本/软删除字段和全部菜谱图片。
- [ ] 首版明确不包含库存、购物清单、制作记录、最近浏览、运行中导入任务、计时器、设置、API Key、Token、Cookie、OCR 模型、缓存和临时文件。
- [ ] `0` 道菜谱可以创建合法空备份，并可被另一空库或非空库预检。
- [ ] 用户文件扩展名为 `.airecipe-backup`；应用按 Manifest 和 Dataset 版本读取，不依赖备份来源设备的 SQLite schemaVersion 或绝对路径。
- [ ] 必需图片缺失、不可读或哈希不匹配时，创建全量备份失败且不交付半成品文件。
- [ ] 导入前显示来源版本、备份时间、菜谱/分类/图片数量、预计空间、新增、相同、可能重复、冲突和不可导入项。
- [ ] 默认“合并”不会删除当前库；同一 UUID 且内容一致时可跳过，同一 UUID 内容不同时必须进入冲突处理，不得静默覆盖。
- [ ] 冲突允许保留当前、使用备份或两者都保留；“两者都保留”生成新的稳定 ID 并保留来源关系。
- [ ] “替换当前库”只能从高级恢复进入，执行前必须创建并验证当前库回滚备份；回滚备份失败时不能继续替换。
- [ ] 导入提交前使用 staging；失败或取消后不留下半完成数据库、断图、孤立媒体或未清理临时目录。
- [ ] 损坏包、非法路径、压缩炸弹、重复路径、未知必需能力、未来不兼容版本和空间不足会在写入当前库前被阻止。
- [ ] 未知可选 Dataset 只有在明确展示跳过内容及影响、用户确认后才可继续。
- [ ] 用户取消文件选择不显示错误；权限拒绝、文件不存在、空间不足和导入失败提供可操作中文说明。
- [ ] 备份中不包含 API Key、Token、Cookie 或安全存储引用；导出成功页提示文件可能包含个人备注和图片。
- [ ] iOS 和 Android 分别验证能够创建、预检并恢复同一版本的 `.airecipe-backup` 文件。

### 异常与极限

- 超长菜名、大量食材、长步骤、大量图片和超大菜谱库采用流式写入/读取，不要求把整个备份载入内存。
- 旧版本备份通过迁移链读取；未来版本含未知必需能力时拒绝并提示所需应用版本。
- 导入失败时必须能证明“当前库未改变”或“已从回滚备份恢复”，不能只显示笼统失败。

## 用户故事变更规则

- 新增产品功能时先补用户故事，再建立开发任务。
- 验收标准必须描述可观察结果，避免“体验良好”“正常运行”等不可验证词语。
- 故事完成后，在对应测试目录保存验证记录。
