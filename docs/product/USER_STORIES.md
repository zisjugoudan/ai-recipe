# 用户故事与验收标准

> 本文将产品需求转换为可开发、可测试的用户故事。  
> 产品行为的完整定义仍以 `AI食谱应用产品需求文档.md` 为准。  
> 每个开发任务必须关联一个或多个用户故事。

## 故事地图

```text
进入应用
├── 游客使用
└── 登录与同步

建立菜谱
├── 手动创建
├── 链接导入
├── 截图/视频/文本导入
└── AI 确认与保存

管理菜谱
├── 分类与标签
├── 搜索与收藏
├── 编辑与版本
└── 备份与恢复

实际下厨
├── 调整份量
├── 准备食材
├── 分步烹饪
├── 计时器
└── 制作记录

配置能力
├── 本地/自有 LLM
├── 平台托管 AI
├── 本地 OCR 插件
└── 云 OCR
```

---

## US-001 游客进入应用

**作为一个不想注册的用户，我可以直接进入应用并建立本地菜谱库。**

### 验收标准

- [ ] 首次启动提供“游客使用”和登录入口。
- [ ] 游客不需要手机号、微信或 Apple 账号即可进入首页。
- [ ] 游客可以创建、编辑、删除、分类、收藏和搜索本地菜谱。
- [ ] 游客数据写入本地数据库，关闭并重新打开应用后仍存在。
- [ ] 页面明确说明游客数据不会自动云端备份。
- [ ] 不使用恐吓式弹窗强迫登录。

### 异常与极限

- 本地数据库初始化失败时给出可操作的重试或数据目录说明。
- 存储空间不足时不能静默丢失编辑内容。

---

## US-002 游客登录并合并数据

**作为已经积累本地菜谱的游客，我登录后可以决定如何处理本地数据。**

### 验收标准

- [ ] 登录前显示本地菜谱、分类和购物项数量。
- [ ] 提供“合并到云端”“暂不上传”“使用云端数据”三种路径。
- [ ] 合并前可以预览重复和冲突。
- [ ] 同一来源链接的重复菜谱不会静默覆盖。
- [ ] API Key 不参与普通数据合并。
- [ ] 合并中断后可以安全重试。

---

## US-003 手动创建菜谱

**作为用户，我可以不依赖 AI 或链接手动创建菜谱。**

### 验收标准

- [ ] 至少可以输入菜名、食材和步骤。
- [ ] 食材支持名称、数量、单位、分组和备注。
- [ ] 步骤支持增删、编辑和排序。
- [ ] 未完成内容可以保存为草稿。
- [ ] 保存后立即出现在本地菜谱库。
- [ ] AI 服务不可用时本功能仍完整可用。

---

## US-004 粘贴小红书或抖音链接

**作为用户，我可以粘贴分享链接并看到明确的导入处理过程。**

### 验收标准

- [ ] 应用能从分享文本中识别有效 URL。
- [ ] 能识别小红书、抖音或不支持的平台。
- [ ] 依次显示获取内容、OCR、ASR、AI 生成等实际发生的状态。
- [ ] 用户离开页面后，允许后台执行的任务不会无提示消失。
- [ ] 导入失败时显示具体阶段和可操作的降级入口。
- [ ] 原始链接和来源平台被保留。

### 降级路径

- [ ] 粘贴原帖正文。
- [ ] 上传截图。
- [ ] 上传已保存视频。
- [ ] 手动创建并使用可用 AI 辅助整理。

---

## US-005 确认 AI 生成菜谱

**作为用户，我可以在保存前核对 AI 生成的食材和步骤。**

### 验收标准

- [ ] 显示菜名、简介、份量、食材、步骤、分类和标签。
- [ ] 所有字段可手动编辑。
- [ ] 低置信度字段有文字和视觉提示，不能只依赖颜色。
- [ ] 用户可以查看字段对应的原文、OCR 或字幕证据。
- [ ] 可以只重新生成食材或只重新生成步骤。
- [ ] AI 推测的精确用量必须被明确标识。
- [ ] 未经用户确认不会写入正式菜谱库。

---

## US-006 配置本地或自有 LLM

**作为游客或登录用户，我可以连接本地或自己购买的模型 API。**

### 验收标准

- [ ] 可以新增 OpenAI 兼容配置。
- [ ] 可以新增 Ollama 配置。
- [ ] 可以填写 Base URL、模型名称和可选 API Key。
- [ ] 保存前可以测试连接。
- [ ] 连接测试显示成功能力或具体错误。
- [ ] 可以为菜谱解析、问答、视觉理解分别选择模型。
- [ ] 密钥存储在系统安全存储中，不进入普通导出。
- [ ] 游客不能选择平台托管 AI，但能看到原因和替代方案。

---

## US-007 安装本地 OCR 插件

**作为重视隐私或不想使用云服务的用户，我可以下载本地 OCR 能力。**

### 验收标准

- [ ] 插件列表显示名称、版本、语言、体积和设备要求。
- [ ] 下载前提示存储和移动数据消耗。
- [ ] 支持下载、失败重试、更新和删除。
- [ ] 包校验失败时不能加载。
- [ ] 可以设置默认插件。
- [ ] “仅本地处理”开启后图片不会发送到云端。
- [ ] OCR 结果记录 Provider 和置信度。

---

## US-008 使用平台托管 AI

**作为登录用户，我可以在有配额时使用平台托管 AI/OCR/ASR。**

### 验收标准

- [ ] 未登录时不会偷偷发起托管 AI 请求。
- [ ] 登录用户可以查看剩余配额或限制说明。
- [ ] 配额不足时提供自有 API、本地 Provider 或稍后重试选项。
- [ ] 托管任务失败时返回统一错误而非供应商原始敏感信息。
- [ ] 用户关闭允许上传后，托管视觉/OCR 服务不可被调用。

---

## US-009 查看并管理菜谱

**作为用户，我可以快速找到并打开已经保存的菜谱。**

### 验收标准

- [ ] 首页展示最近查看、分类、收藏和全部菜谱入口。
- [ ] 支持按菜名、食材、标签和备注搜索。
- [ ] 可以调整分类并收藏菜谱。
- [ ] 删除进入回收站，不立即永久消失。
- [ ] 无菜谱、搜索无结果、图片缺失和超长标题都有明确状态。

---

## US-010 烹饪模式

**作为正在做菜的用户，我可以逐步查看操作并使用计时器。**

### 验收标准

- [ ] 一屏突出一个步骤。
- [ ] 可以前后切换步骤。
- [ ] 显示该步骤相关食材、火候和时间。
- [ ] 含时间的步骤可以一键启动计时器。
- [ ] 多计时器可以并存并明确区分。
- [ ] 计时完成有本地通知。
- [ ] 大字体、系统字体缩放和高对比度可用。
- [ ] 无网络时仍能使用已保存菜谱和计时器。

---

## 用户故事变更规则

- 新增产品功能时先补用户故事，再建立开发任务。
- 验收标准必须描述可观察结果，避免“体验良好”“正常运行”等不可验证词语。
- 故事完成后，在对应测试目录保存验证记录。
