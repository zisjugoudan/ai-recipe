# Bug 交接：链接导入配图下载 403 与 WebView 网页加载超时（IMPORT-008）

> 交接人：Codex（实现方）
> 接收人：高级工程师

> 关联：`ADR-0018`、`ADR-0019`、`SPK-007`、`IMPORT-006`、`IMPORT-008`、`R-018`

## 1. 一句话现状

链接导入（小红书优先）从"客户端直连下载图片全部 403"改为"内置 WebView 浏览器内核抓取"（IMPORT-008）后，文本能提取，但**图片仍取不到**：上一轮是浏览器会话取图后 Dart 侧仍 403（本地图片列表为空、回退直连），修复后再测出现**新的失败模式"网页加载超时"**。

## 2. 目标与背景

- 用户需求：从链接添加菜谱时获取小红书配图（IMPORT-006），并改用浏览器环境保存网页真实文本和图片（IMPORT-008），后续扩展任意平台。
- 已验证事实：**客户端直连（Dart `SecureSocket`/BoringSSL、各种 UA/Referer/IPv4/IPv6）请求小红书图片 CDN 全部 403**；同一 URL 用 Windows curl、真机浏览器打开均 200。即 CDN/WAF 按"客户端特征"拒绝非浏览器请求，客户端侧怎么调都无效，因此必须让图片字节走浏览器网络栈。
- 决策（ADR-0018）：全面替换直连 Adapter，后台隐藏 WebView 加载，保存网页真实文本与图片，通用任意 URL。

## 3. 完整时间线与现象（含证据）

| 阶段 | 现象 | 证据/说明 |
|---|---|---|
| 1. 直连阶段（IMPORT-006） | 配图全部 403，草稿无封面 | Logcat `[AIRecipe][RemoteImage] status=403`；DNS 解析大量 IPv6 在前，客户端固定连第一个地址被 403；已做 IPv4 优先 + 地址级故障转移，仍 403；Windows curl/浏览器同 URL 200 |

## 4. 当前实现关键点（修复后代码）

文件：`code/apps/mobile/android/app/src/main/kotlin/com/airecipe/ai_recipe/webview/WebViewFetchMethodHandler.kt`

1. **加载**：后台隐藏 WebView（1×1 挂载 decorView），桌面 Chrome UA，`loadUrl` 目标地址。
2. **提取**：`onPageFinished` 后固定延迟 2.5s，`evaluateJavascript` 注入平台脚本（小红书走 `window.__INITIAL_STATE__` 递归定位笔记对象，兼容分享页）。
3. **取图**：提取到图片地址后执行第二段 JS：`fetch(升级为 https 的图片URL)`（不带 credentials）→ `blob` → `FileReader` → base64 → 调用注入桥 `AiRecipeBridge.onImagesDownloaded(json)` 异步回调 Kotlin → 写 `filesDir/webview-images/img-N.<ext>` → 返回 Dart `images[]`（localPath）。
4. **超时**：`fetchPage` 设置 45s `timeoutRunnable`，超时直接 `completeError("timeout")`。
5. **诊断**：WebChromeClient 把页面 console 透传 Logcat；桥回调、写文件、Dart 回退均有日志。

## 5. 本轮修复内容（针对上一轮 403，尚未验证）

- JS fetch 前把 `http://` 图片地址升级为 `https://`（避开 https 页面混合内容拦截）。
- fetch 去掉 `credentials: 'include'`（CDN 返回 `Access-Control-Allow-Origin: *` 时凭证模式跨域会被 CORS 拒）。
- 用 `addJavascriptInterface` 异步回调替代依赖 `evaluateJavascript` 等待 Promise。
- 增加三层诊断日志（console 透传 / 桥回调 / Dart 回退）。

## 6. 疑点清单（请高级工程师判断方向）

### A. 关于"网页加载超时"（最新）
1. **45s 内 `onPageFinished` 未触发**：小红书 PC 页面对无登录、无 Cookie、桌面 UA 的 WebView 访问，可能触发风控、无限重定向或长时间 pending 资源（懒加载图片/CDN），导致 `onPageFinished` 迟迟不来，45s 硬超时。→ 方向：超时放宽 / 不依赖 `onPageFinished` 改轮询 DOM / 监听加载进度（`onProgressChanged`）判断渲染完成。
2. **提取/取图阶段挂起**：`onPageFinished` 已触发但 `evaluateJavascript` 回调未返回（页面 JS 引擎被阻塞、脚本异常），也会表现为超时。→ 方向：给 JS 提取阶段加独立超时与错误捕获，输出诊断。
3. **行为是否与上一轮不同**：上一轮同链路能提取出文本与图片地址（说明页面加载成功过），本轮"网页加载超时"是换了链接、小红书风控升级，还是本轮代码改动引入（`addJavascriptInterface`/`WebChromeClient`/混合内容设置不影响页面加载，理论上无影响，需日志确认）。

### B. 关于图片字节获取（核心未解）
4. **WebView JS 跨域 fetch 依赖 CDN 的 CORS 头**：若 CDN 不返回 `Access-Control-Allow-Origin`（或返回但 https 升级后证书/重定向异常），fetch 会被浏览器拦截。→ 方向：改用 `WebViewClient.shouldInterceptRequest` 在 **WebView 网络栈**里直接下载图片字节（不经过页面 JS、不依赖 CORS），这是更可靠的"浏览器会话取字节"方式。
5. **WebView 会话 Cookie/登录态未使用**：WebView 无 Cookie，小红书对无登录访问可能返回登录墙/降级内容。→ 方向：是否允许复用用户浏览器登录态（隐私边界，ADR 需决策），或确认目标笔记在无登录下可访问。
6. **纯 JS 取图方案的稳定性**：依赖 SPA 渲染时序 + 固定 2.5s 延迟 + CORS + 混合内容，脆弱点多。→ 方向：是否改为"WebView 加载 → `shouldInterceptRequest` 收集浏览器实际发起的图片请求并缓存字节"或"页面加载完成后用 `loadData` 嵌入 `<img>` 由 WebView 自身加载"（display 类资源不受混合内容 fetch 限制，且天然带浏览器特征）。

### C. 其他
7. 桌面 UA 在真机 WebView 上的可用性是否稳定（小红书是否对 WebView 用户代理指纹风控）。
8. 45s 超时对普通网页是否够用（普通网页也可能资源多）。

## 7. 已尝试但无效/不完整的方向（避免重复踩坑）

- 客户端直连下载（`PinnedHttpsOcrImageDownloadClient`）：IPv4 优先、地址级故障转移、各种 UA/Referer/http↔https、强制 IPv4/IPv6 节点——**全部 403**，方向关闭。
- WebView 内 JS `fetch` 下载：能拿到图片地址但本地文件列表为空（403 现象），修复（https 升级/去 credentials/异步桥）后未验证即出现"网页加载超时"新现象。
